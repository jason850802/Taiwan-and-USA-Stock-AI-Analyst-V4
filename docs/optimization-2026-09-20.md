完成日期：2026-09-20。效能對照量測於 2026-09-18，最後瀏覽器驗收於 2026-09-20。

本輪已完成資料處理加速、首屏載入縮減、搜尋取消與程式清理。行情與金額計算輸出維持相容；費率、匯率沿用窗、分析規則與提示詞未變更。

行情量測使用相同假資料、同一台機器與 Node v26.4.0，每組五次取中位數，走公開 `getStockData` 管線並強制略過行情快取。包含資料轉換、指標計算與序列化，不包含真實網路延遲。四組完整輸出的 SHA-256 前後全部一致。這些百分比不等於正式網站整頁載入提速。

首屏基準是本次接手時的工作區，已包含原有圖表／報告延遲載入修改；表內的減少量是本輪進一步改善。KiB 以 1,024 bytes 計算；不含 CSS、使用功能後才下載的模組與行情資料。

具體變更：

- **日期轉換重用格式器**：依時區與格式重用 `Intl.DateTimeFormat`，避免每根 K 棒反覆初始化；快取限制最多 32 組。日期、夏令時間、指標與歷史深度保持原規則。
- **庫存報價共用同時進行的請求**：相同正規化代碼的重疊讀取共用一次請求；測試中 10 次並行讀取只送出 1 次行情請求。強制更新仍發出新請求；失敗後可以重試，舊請求不會覆寫較新請求的快取。
- **所有 AI 入口延後下載**：市場分析、基本面、買進分析、單檔及批次庫存健檢皆在執行分析時才載入 Gemini 模組；保留原本的錯誤處理與提示詞。
- **減少無關圖表重繪**：圖表使用 React memo，移除未使用的回呼傳遞；搜尋文字改變不再使整個圖表因父層渲染而跟著重繪，圖表自身操作與均線設定仍會更新。
- **搜尋並行與取消**：海外搜尋與台股名錄並行載入；輸入新內容、清空、選取、送出、Escape、元件卸載及父層快捷選股都會讓舊查詢失效。維持本地結果先呈現、最後合併去重的行為。
- **搜尋回饋與可及性**：新增搜尋中狀態，以及搜尋框／結果清單／選項的語意標記與鍵盤選取關聯。
- **移除確定未用的程式**：清除 11 項編譯器指出的正式程式宣告或參數，包括未用型別／import、格式化函式、區域變數、圖表屬性及回呼；合併重複的日期格式器設定。

新增防競態邏輯、測試與量測工具後，儲存庫總行數並未大幅下降；本輪瘦身的主要效益是減少首屏下載、重複初始化與無效工作。沒有為了降低行數移除仍有用途的功能。

## 全專案掃描範圍

透過 TypeScript 模組解析掃描 91 個正式程式檔，涵蓋 App／入口、components、services、utils、config 與 api。91 個都能從應用或 API 入口循引用到達，未找到可直接刪除的整個孤立檔案。此掃描包含型別引用，只能排除明顯孤立檔案，不能證明每個 export 或執行分支都會被使用。

人工重點檢查資料請求、快取、搜尋、圖表、AI 串流、庫存報價、基本面、儲存、後端握手與共用視窗。既有 `.planning/codebase` 文件是較早快照，部分內容已被現況修正，例如後端代理、錯誤邊界、測試及重複的舊分析流程；本報告依現行程式判斷。

## 後續改善優先順序

以下是本輪盤點的建議，尚未實作。靜態發現與待量測的效能假設分別標示，避免將推測當成實測成果。

| 優先 | 問題與依據 | 使用者影響 | 建議與驗收 |
|---|---|---|---|
| P1 | [基本面請求](../components/FundamentalsPanel.tsx)缺少請求世代守衛，`activeSymbol` 只在成功後更新；已有資料時也沒有換股載入覆蓋。靜態確認。 | 快速換股時舊回應可能蓋回新結果；第二檔失敗後，「重試」可能抓前一檔；等待期間容易把舊內容當新資料。 | 獨立記錄目前請求代碼、限制結果只屬於最新請求，提供換股載入狀態。驗收 A 慢／B 快、B 失敗重試及 AI 生成中換股。 |
| P1 | [K 線背景刷新](../services/yahoo.ts)已有相同請求時直接 return，沒有登記後來呼叫端的 `onRevalidated`。靜態確認，尚未做專用重現。 | 快速切離再切回同一檔時，原回呼可能已過期，新畫面收不到補全通知而停留舊圖。 | 共用網路請求，同時維護有效訂閱者或讓每個呼叫端等待同一補全；以慢速回應及切頁情境鎖住結果。 |
| P1 | [庫存報價 UI](../components/portfolio/useHoldingPrices.ts)沒有逐代碼請求世代守衛。服務層本輪已保護快取，但 UI 仍直接套用各次 await 結果。靜態確認。 | 舊載入與手動強制更新重疊時，畫面仍可能被較晚抵達的舊結果覆蓋。 | 針對每檔報價與匯率維護最新請求身分，驗收兩種回應先後順序；維持既定匯率與快照口徑。 |
| P2 | [庫存批次抓價](../components/portfolio/useHoldingPrices.ts)用 `forEach` 同時啟動所有不同代碼；[Yahoo 後端](../api/_lib/yahoo.ts)冷啟動的 cookie／crumb 握手也未共用進行中請求。 | 多檔持股同時更新容易形成請求尖峰；實際限流及延遲程度仍待量測。 | 共用既有併發工具，先量測多檔持股；後端加同一執行個體內的握手共用，保留驗證失效與重試行為。 |
| P2 | [行情快取](../services/quoteCache.ts)同步序列化完整 K 線，記憶體 Map 無容量界線；[基本面快取](../services/finmind.ts)以日期分 key 而未清除舊日期。 | 長時間大量切股可能累積記憶體與同步儲存停頓；目前尚無長時間量測。 | 先記錄記憶體與主執行緒停頓，再加可重建快取的容量／淘汰策略或延後持久化；本體資料不得被快取清理牽連。 |
| P2 | AI 串流每次增量更新都把完整文字交給 [MarkdownReport](../components/ui/MarkdownReport.tsx)重新解析。 | 長報告可能逐漸增加渲染成本；尚未做長報告壓力測試。 | 以固定長文字串流量測，合併同一畫面更新週期的文字增量，完成時立即呈現全文；不改 AI 請求與報告內容。 |
| P2 | [共用視窗](../components/ui/Modal.tsx)有 Escape 與初始 focus，但未限制 Tab 留在視窗內，也未還原原焦點；指標設定部分圖示按鈕沒有可讀名稱。靜態與畫面觀察。 | 鍵盤操作或螢幕閱讀器使用者容易失去位置。 | 加入焦點循環與關閉後焦點還原，替圖示按鈕加操作名稱；用全鍵盤驗收新增、匯入與分析視窗。 |
| P3 | 行情、圖表、AI 規則各仍超過千行；規則文件有歷史資訊與現況混用。 | 後續維護較難定位，也容易重做已處理的最佳化。 | 依可獨立驗收的職責逐段整理；保留 AI 提示詞逐位元組鎖及金融行為鎖，新增現況說明而不重寫歷史快照。 |

建議下一批先完成前三項「資料屬於哪次請求」的防護，再處理多檔請求尖峰與長時間使用的快取／渲染成本。快取新鮮度與金額語意若有調整，需另行攤開現值和影響確認。

## 驗證與限制

- 完整 `npm run gate` 通過：TypeScript、40 個測試檔共 727 項測試、正式建置、金鑰掃描、package／lock 零變更。
- 本次開始時的 713 項既有測試與 snapshot 均未修改，新增 14 項公開服務行為測試。
- 額外未使用宣告掃描：正式程式的原有警告已清除；既有 `utils/backfillPipeline.test.ts` 一項未用測試 import 保留，以遵守既有測試零修改。
- 假資料瀏覽器驗收：市場／庫存／基本面分頁、週線切換、縮放、均線 MA5 改 MA7、鍵盤搜尋選股、清空搜尋、行情失敗提示、重試恢復、未完成搜尋後快捷選股再聚焦，均通過。
- 畫面假行情價格讀值為 150.39；目前 456px 視窗量得頁面寬度也是 456px，沒有整頁水平溢出。這不代表所有手機／平板或大量庫存表格已驗收。
- 正常主要分頁與最終回復頁面未捕捉到 console error。AI 使用本機拒絕回應驗證錯誤與重試提示；未呼叫真實 AI，未驗證模型輸出。
- 驗收站所有 `/api` 都由本機假資料攔截；未寫入真實庫存、未新增套件、未部署或發版。工作區既有修改保留，尚未提交 Git。

## Standards

獨立規範覆核：無硬性違規，無需處置的程式異味。確認保留領域型別、費率與提示詞，未修改既有測試；格式器有容量上限，報價有失敗清理與快取競態防護，搜尋有取消與過期回應檢查。
