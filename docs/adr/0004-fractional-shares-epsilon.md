# ADR-0004: 美股碎股——容差進引擎、精度歸儲存、取整只留顯示

- 日期：2026-08-04
- 狀態：已拍板（grill 四題四答，使用者逐題確認）
- 階段：邊界決策；實作規格見 `.scratch/fractional-shares/spec.md`；偵查證據見同目錄 RECON.md

## 背景

使用者以定期定額買入美股碎股（實例：LITE 三批 1.2048／1.08896／0.50824，合計 2.802 股）。
資料模型與對帳單解析器自 Phase 11 起就支援小數股數（`ParsedTxn.shares` 註明可為小數、
解析器用 parseFloat、碎股解析有行為鎖案例），**儲存層從來沒有壞**。壞掉的是兩層：

1. **顯示層**：股數格式化預設 0 位小數，群組列把 2.802 四捨五入成 3；
   已實現帳本、匯入缺口列、賣出視窗共四處同病。
2. **匯入重播引擎**：「池子夠不夠賣」用無容差的 `<` 比較。三批碎股的浮點加總是
   2.8019999999999996，比對帳單賣出的 2.802 少 4.4e-16 → 誤判持股不足 →
   產生「賣出 0 股找不到買進紀錄」的幻影缺口 → 整筆賣出被略過，庫存沒扣、帳本沒記。

## 決策

1. **碎股是市場層能力，不做標的白名單。** 本 App 是記帳不是下單——「哪些美股標的
   可以碎股交易」是券商的規則，對帳單與使用者輸入本身就是事實來源。美股一律允許
   小數股數；台股維持既有行為（整數防呆本輪不做，見決策 5）。

2. **單一容差常數 `SHARE_EPS = 1e-6`（0.000001 股），語意＝「浮點噪音的上界」。**
   - 依據：券商碎股最小單位是 1e-5（國泰對帳單股數最多 5 位小數），浮點加總的
     累積誤差量級約 1e-13～1e-16；1e-6 比最小真實單位小一個數量級、比噪音大七個。
   - 匯入重播引擎的缺口閘門：`賣出股數 − 池子加總 > SHARE_EPS` 才成立缺口；
     容差內視為足額賣出（吃整池）。金額守恆不靠容差——靠既有的「末筆吃餘數」分攤。
   - 手動賣出引擎：超賣擋板放寬為 `賣出股數 > 持有股數 + SHARE_EPS` 才拋錯；
     滿賣判定放寬為 `持有股數 − 賣出股數 ≤ SHARE_EPS`；容差內一律**以持有股數為準
     （clamp）**入帳，成本基礎比例永不超過 100%，也不再產生塵埃批次。
   - 容差**只放寬噪音級邊緣**：整數與精確值路徑行為不變，既有測試案例零修改由設計保證。

3. **精度歸儲存、取整只留顯示，兩者永不互滲。**
   - 儲存的股數永不 rounding（現狀維持）。
   - 顯示統一走新的 `fmtShares`：先 round 到 6 位小數吸掉浮點噪音、去尾零、千分位
     （2.8019999999999996 →「2.802」、1.08896 →「1.08896」、3 →「3」、12000 →「12,000」）。
   - **fmtShares 禁入任何輸入欄**：明細編輯格與「全部」鈕維持 `String(value)` ↔ `parseFloat`
     的精確往返（千分位逗號會讓 parseFloat 把 2,802 讀成 2）。這是使用者「明細正確」
     的根基，列為紅線。

4. **匯入紀錄語意維持「確認即記鍵」。** 按「確認匯入」時，被略過的交易（沒補成本的
   缺口賣出）其去重鍵照舊記為已匯入——「留空略過」是使用者的決定，記鍵＝記住這個決定。
   本次 LITE 被幻影缺口誤傷屬引擎 bug 的一次性後果，用 Console snippet 清鍵修復，
   不為它改動去重語意。（引擎修好後，幻影缺口不再發生，這條語意不會再誤傷人。）

5. **台股整數防呆本輪不做。** 新增／編輯表單目前收得進 0.5 股台股，實務上不會發生；
   與本次碎股修正無關，留待日後有真實需求再開票。

## 後果與約束

- **既有測試案例零修改**（專案紅線）：容差全部作用在「噪音級」邊緣，
  整數／精確值案例的可觀察行為不變；新增案例不受限。
- 匯入重播引擎其餘機制**零變更**：FIFO、末筆吃餘數、費用取帳單實數（D-06）、
  塵埃批次 1e-9 過濾、乘先除後。
- 流水回推引擎**零變更**：它的賣出迴圈本來就有 1e-9 防護＋「賣超忽略」語意。
- 解析器**零變更**：碎股解析已有行為鎖（Case G）。
- 備份 schema **不升版**：本次沒有任何資料模型欄位變更。
- `SHARE_EPS` 是**單一常數單一出處**，匯入重播與手動賣出共用；兩邊各自寫死數字
  即視為違反本決策。
