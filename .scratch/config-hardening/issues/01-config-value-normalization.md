# 01 — 設定值與參數的靜默降級收口

**What to build:** 讓「設定或參數打錯」這件事在正確的地方浮現，而不是變成離原因很遠的另一種症狀。
四個具體走向（來源＝`.scratch/api-lib-tests/findings.md` 第 5、6、7 條，2026-07-28 使用者裁決要修）：

1. **模型名只有空白時落回預設**。現行：空白字串是 truthy，`||` 攔不住，會原樣被當型號送去上游，
   使用者看到的是「模型無法使用」而不是「設定打錯」。改為：取值後去頭尾空白，空了就用預設型號。
2. **允許來源的尾斜線全部去掉，不是只去一層**。現行：`https://a.example//` 正規化後留下
   `https://a.example/`，永遠比不中瀏覽器送的 Origin（不帶尾斜線），該白名單項實質失效，
   而部署方以為整個網域都設好了。
3. **shared secret 設定存在但為空時，留下可見的警告**。現行：空字串與未設同路，驗證無聲停用；
   Vercel 環境變數貼上失敗就會這樣，而部署方以為開著。
   **不要改變放行行為、不要 throw**——只要讓它在 log 裡看得見（現行 fail-open 的
   `console.warn` 是同類先例）。
4. **FinMind 的日期要驗真實曆法**。現行只驗形狀，`9999-99-99`／`2021-02-29` 都會通過並送往上游，
   使用者看到「查無資料／上游錯誤」而非「日期打錯」。改為：形狀過了之後還要是真實存在的日期，
   不是就丟 `BAD_REQUEST`。

**Blocked by:** None — can start immediately.

**Status:** resolved

## ⚠️ 兩個必讀的前提

**serverless 沒有啟動期，禁止在模組載入時 throw。** 這幾個值都是隨呼叫讀取的；若改成
載入期驗證失敗就拋錯，一個設定打錯會讓所有端點在冷啟動時整片 500——比現在的靜默降級更糟。
一律走「正規化 ＋ 必要時 warn」，不走 fail-fast。

**現有行為鎖會紅，那是它該做的事。** `api/_lib` 的測試逐字鎖住了上面這些現行行為
（空白型號原樣回傳、尾斜線只去一層、日期只驗形狀等）。本票是**有意識的行為變更**，
要連同把對應的斷言改成新行為並在 commit 說明改了哪幾條。**不准為了讓測試綠而回頭改產線碼**，
也不准把測試案例整條刪掉——改斷言、保留案例的敘事。

## Comments

**2026-07-28 完成。** 走真正的 TDD：先把行為鎖改成新行為（**確認紅燈 5 條、其餘 55 條
不受波及**），再改產線碼轉綠——這批鎖是上一輪剛立的，正好用在它們被設計來守的場合。

四個走向的實作取捨：
- 型號名用 `?.trim() ||`，順帶把「值前後有雜空白」也一起修掉（未設時 `undefined?.trim()`
  仍是 undefined，落回預設的行為與改動前逐字相同）。
- 尾斜線 `/\/$/` → `/\/+$/`。**只改 config 的白名單值**，沒動 guard 對「進來的 Origin」
  的正規化——瀏覽器不送尾斜線，改它是沒有需求的抽象。
- 空 secret 的警告用 module 級旗標做到每個實例只喊一次（每請求都喊會洗版 Vercel log）。
  未設不喊——那是本機 dev 的正常降級路徑。**放行行為零變更**。
- 曆法檢查用 ISO 字串往返比對，不用 `Date.UTC()` 逐欄比對——後者會把 `0050` 這種
  兩位數年份映射成 1950，誤殺真實日期（node 實測確認）。

故障注入 9 條全紅，含「只喊一次」與「未設不喊」這兩個容易寫成裝飾的斷言
（注入「改成每次都喊」「未設也誤喊」都會紅）。
code-review 收一條：既有「空字串回空字串」那條測試沒接 warn，會讓測試輸出多一行雜訊。

**沒做的**：findings 第 2、11、12 條（已裁決維持現狀）、第 13 條（暫緩）。
