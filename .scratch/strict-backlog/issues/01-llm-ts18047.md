# 01 — 收斂 Claude CLI child process stdio 的 TS18047

Status: resolved（2026-07-30）
Blocked by: —（首票）

## What to build

修正 `api/_lib/llm.ts` 內 Claude CLI 非串流與串流兩條執行路徑的 child process stdio 型別契約，讓 TypeScript 能正確知道這兩條路徑的 `stdin`、`stdout`、`stderr` 可供讀寫，消除本票對應的全部 TS18047。實作應以一個能反映真實執行期 invariant 的集中式做法處理，例如精確表達 `spawn` 的 pipe 契約，或在適當邊界做一次明確的執行期檢查；不要分散加入非空斷言逐點消音。

本票只處理這組 nullable stdio 欠帳。必須保留既有 Claude CLI 的參數與環境、prompt 經 stdin 傳入、非串流 JSON 解析、串流逐段解析與 `onDelta`、取消、同步與非同步 spawn 失敗、stdio stream error、timeout、close、快取清除及單次 settle 語意。不得順手處理其他 strict 錯誤，也不得改變任何對外成功結果、錯誤分類或錯誤訊息。

## Comments

**2026-07-30 完成。** 修法＝**精確表達 spawn 的 pipe 契約**，不引入執行期 guard、不加任何非空斷言。

根因：兩條路徑都寫 `let child: ReturnType<typeof spawn>`。`spawn` 是 overload 函式，
`ReturnType` 只取**最後一個** overload 的回傳型別（`ChildProcess`，三條 stdio 皆 nullable），
真正命中的那個 overload（未指定 `stdio` → `SpawnOptionsWithoutStdio`）回傳的
`ChildProcessWithoutNullStreams` 反而被這行標註蓋掉。改標 `ChildProcessWithoutNullStreams`
即讓型別與真實 invariant 一致（`@types/node` 22.19.15，`child_process.d.ts:586`／`846`）。

diff 只有 5 行：import 加 `type ChildProcessWithoutNullStreams`、兩處 `let child:` 換型別、
兩段既有註解補說明。**零執行期敘述變動**——三個 `.on('error', () => {})`、try/catch、
timeout／settle／cancel／close 收斂、JSON 與串流解析全部逐位元組不動；`type` 修飾字在
emit 時被抹除（同檔 line 10 的 `type GeminiRequest` 已是先例），不新增任何 runtime import。
