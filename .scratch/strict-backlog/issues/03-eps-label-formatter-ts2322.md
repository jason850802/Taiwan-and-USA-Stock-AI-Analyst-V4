# 03 — 收斂 EPS 數值標籤 formatter 的 TS2322

Status: resolved（2026-07-30）
Blocked by: —（triage 的四個修復單元彼此獨立，票 01 已 resolved 不構成前置）

## What to build

修正季度基本面圖表中「EPS 長條圖數值標籤」formatter 的型別契約：讓它接受圖表函式庫
`LabelFormatter` 宣告的**完整輸入範圍**，再於函式內自行收斂到數字後格式化，消除本票對應的
TS2322。根因是參數反變性——目前的 inline callback 把輸入縮得比函式庫宣告的更窄，
除了型別不合，也代表非數字輸入在執行期會落進「對非數字呼叫數字方法」的路徑。

**不得只用型別斷言、`any` 或 `as` 繞過**：那會讓型別過關但把同一個執行期風險原封不動留著，
正好是 triage 點名要避免的做法。

本票只處理這一個 formatter 的型別欠帳。EPS 標籤的顯示結果必須逐字維持現狀：有值顯示小數
兩位、無值顯示空字串。**0 與負數都是「有值」**——收斂條件不可退化成 falsy 判斷，否則 0 會
從 `0.00` 變成空白。不得順手處理其他 strict 錯誤，也不得改動圖表的其他設定（動畫開關、
座標軸、Tooltip、顏色、資料鍵）或另一張三率圖。

## Comments

**2026-07-30 完成。** 修法是把參數放寬到函式庫宣告的完整 `RenderableText`
（`string | number | boolean | null | undefined`），再以 `typeof v === 'number'` 收斂後才
呼叫 `toFixed`。同時把原本寫在 JSX 內的 inline callback 提成模組層具名 const（與同檔既有的
季度軸格式化同一種寫法），並 export 出來上行為鎖。零型別斷言、零 `any`。

### 行為鎖與故障注入

新增 7 案覆蓋 `RenderableText` 全範圍：正數／負數／0 與 `-0`／`null`／`undefined`／字串／
boolean。兩次故障注入證明鎖不是裝飾品：

| 注入 | 紅燈數 | 紅在哪 |
|---|---|---|
| 退回 `v != null`（放寬前寫法） | 2 | 字串與 boolean → `TypeError: v.toFixed is not a function` |
| 退化成真值判斷 `v ? … : ''` | 3 | 上述 2 案，**再加** 0 的 `expected '' to be '0.00'` |

### 一處驗收條件寫得不對（如實記錄）

上面第 4 條要求「0 顯示小數兩位」以 DOM 讀值佐證，**這條在 DOM 層無法照字面成立**：
EPS 恰為 `0` 時 recharts 根本不畫零高度長條，`LabelList` 也就沒有標籤節點可讀。
控制組（注入 `0.001`）證明問題不在 formatter——該筆有長條，標籤文字literal 就是 `"0.00"`。
所以「格式化成 0.00」在真實 DOM 有直接證據，只是承載它的那根長條在**精確 0** 時不存在。

這是既有 recharts 行為，放寬型別前後完全相同，非本票所致；已登記為 findings **F-01** 交由
使用者裁決，未順手修改。0 的 formatter 層行為由上述行為鎖（含故障注入）鎖住。
