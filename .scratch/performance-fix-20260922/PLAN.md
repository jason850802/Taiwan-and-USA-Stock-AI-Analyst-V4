## 3. 成功定義與量測口徑

### 硬性正確性門檻

- 相同固定上游輸入下，最終行情、交易日、OHLC、成交量、指標、篩選與金融計算輸出維持一致；名稱補入前後只允許名稱／顯示完整度改變。
- force、同 key 去重、舊請求失效、移除／重加、卸載、快取發布世代及匯率規則都維持。
- 名稱失敗不能令有效報價失敗；名稱晚到不能覆蓋新價格、重新延長報價沿用窗、修改本體資料或誤觸發健檢。
- 正常案例沒有非預期 console error；失敗注入的預期錯誤另記。既有測試／snapshot、package／lock 不變，完整 gate 通過。

### 本計畫提出的效能驗收目標

以下是**待本計畫採用的工程門檻**，不是已量得的承諾。01 在看到候選結果前凍結量測方法；若門檻不適用，記錄原因與修訂，不能事後調低到剛好通過。

| 指標 | 驗收方式／目標 |
|---|---|
| 本機空 OPTIONS | Yahoo chart、FinMind 分路由比較；候選中位數不超過同期精簡對照的 `1.25 倍 + 250 ms`，且全部 204、無逾時。若原工作區仍重現異常，候選相對其中位數至少降低 50%。 |
| 名稱阻塞 | 固定回應控制器讓 Yahoo 已完成、名稱持續 pending；正式 hook 必須可顯示有效價格且讓下一筆價格任務起跑，無須釋放名稱回應。名稱稍後補入、失敗或逾時皆有案例。 |
| 十檔真行情 | 同期原基準仍重現慢速時，候選「首個有效報價」及「全部有效報價＋匯率」的批次中位數各降低至少 40%；逐列成功率不下降。未達成就記為未通過，不用快取命中或失敗快速結束充數。 |
| 十／三十檔固定行情 | 保留既有三槽對照；量首檔、全部、排隊、實際 HTTP 峰值、名稱補齊及匯率完成。價格改善不得以取消、漏項或背景無界併發換取。 |
| K 線使用者等待 | 分別量「送出搜尋→第一批有效 K 線可見」與「完整歷史／必要 context 完成」，並量 API TTFB；不再拿 HTTP 完成時間冒充畫面完成。 |
| 回訪 | 同分頁、沿用窗內，固定十檔各回訪一次，記錄新增 chart 請求數；與同配置基準比較。搜尋 API、名稱 API 分開統計。 |

若全新原工作區已與精簡對照同速，01 先記錄「舊慢速未重現」及冷啟動差異；不得用歷史 6.607／42.02 秒充當同期 before，亦不得要求候選對正常基準硬減 40%／50%。此時可繼續可穩定重現的名稱阻塞修復，但本機根因修復只能標為未證實，直到取得有效的重現／對照。

### 共用量測協定

1. 保存 commit、未提交來源 manifest、工具雜湊、實際 serve／build 身分、Node／Vercel／瀏覽器版本、來源 root、origin、PID、port、時區與快取模式；環境變數只保存名稱及一致性檢查結果，不保存秘密值或秘密雜湊。
2. 新建 `evidence/<票號>/<run-id>/`，輸出已存在即拒絕覆寫；每組結果綁定本輪身分。既有診斷工具輸出路徑固定，不能原樣重跑覆蓋舊檔；另作參數化工具並驗證從保存位置可重跑。
3. OPTIONS：每環境／路由先記一次冷啟動，再做至少 5 個交錯配對暖回合；至少兩次獨立服務啟動。冷與暖分開；逾時列為失敗，不能排除後只算成功樣本。負載／父程序條件不一致時不做因果推論。
4. 固定行情：固定代碼、回應、時間、順序與 cache 狀態。至少 5 次有效回合；以可控制 pending／完成順序的斷言測阻塞與競態，不用脆弱的幾毫秒單元測試取代行為驗證。
5. 真行情十檔沿用診斷的五台股＋五美股，三個配對批次交錯 before／after；三十檔清單在 01 固定，最終各做一批前後對照，僅稱觀察值。每批分清全冷、同頁暖回訪及 force，不混算。小樣本報原始值、中位數與範圍，不報 p95／SLA。
6. 真行情只在基準與選定候選做有界驗證，不對每種併發跑大量上游壓測。先列請求預算；遇 429／持續 5xx／逾時就結束該批、保留結果並遵守上游等待要求，不用密集重試湊成功。
7. 報價時間點須拆開：任務入列、HTTP 開始、headers、body 完成、有效價格可見、匯率完成、名稱補齊。失敗解除 loading 只算 settled，不算成功；原診斷 probe 的完成判斷需補上逐列 `error=false` 與有效價格。
8. 真行情只掛載合成 symbol/id 的正式 hook，不掛本體儲存流程；五把本體 key 前後逐值一致。正式 App 用隔離 origin／瀏覽器儲存及合成持股驗證快照／健檢，不使用使用者真帳本。

### 04 — 價格先完成，名稱另行補入

**預期行為：**Yahoo 有效價格到達後即可顯示並釋放價格工作；已有中文名稱就沿用，沒有時顯示既有名稱／Yahoo 名稱／代碼，中文名稱可稍後補齊。

**工作：**

**必驗案例：**名稱命中／慢／失敗／逾時、價格失敗、同碼共享、force 覆蓋一般請求、連續 force、新價先到舊名稱後到、移除／重加、卸載、匯率先到／晚到／失敗、快取回讀及跨沿用窗。所有競態同時驗 UI 和記憶體／session 快取。

**回復：**以本票單獨提交回復名稱解耦；不撤回既有 04／05 票的身分守衛或佇列。

- 維持跨重疊刷新共用上限、同 key 合併、已啟動工作占槽至結束、FX 優先及移除取消規則。名稱流量一併計入，禁止以背景請求避開上限。
- 原三槽達目標就保持三槽、交付量測結論。若其他上限有穩定收益，先提交比較與所需測試契約變更；依既有測試紅燈規則決定後續，不先改期望值。

**完成：**有可重跑的「維持三槽」或「需另行調整」結論；少量真行情只驗選定候選，不能據此宣稱永遠不會 429。若現有三槽未達整體目標且調整仍待決定，不能讓 07 宣稱全案完成。

### 06 — K 線等待鏈分類，僅處理剩餘瓶頸

先量環境修復後的完整路徑；若目前等待已主要是上游價量取得，保留量測結論，不為拆 Promise 而拆。

| 資料 | 預設處理 | 不可跨越的邊界 |
|---|---|---|
| 中文名稱 | 優先沿用名錄／快取；獨立補入的候選 | 不改 symbol／市場識別、不讓舊名稱回填新股票 |
| FinMind 價量 | 保留必要等待 | OHLC 修正、成交量、日期、指標與選股結果需一致 |
| 法人／籌碼 | 先核所有圖表、濾網及 AI 使用端 | 未到不能當成 0，不能提前標成分析完整；有依賴就保留等待 |
| 2 年／10 年歷史 | 保留原兩階段與訂閱契約 | 短歷史不能污染完整歷史快取／完整歷史使用端 |

**最小修復：**只在名稱仍阻塞時移出純名稱等待，或共用已取得名稱；保留必要價量與籌碼 context。未授權改領域契約時，不新增「尚未修正 OHLC 的 K 線先當正式結果」路徑。

若進一步提前繪圖需要新增 context readiness／分析禁用狀態，先提出獨立設計決策及相容性案例；本票不能直接刪 await，亦不能把 `partial` 同時當作歷史不足與行情未校正而不區分。

**必驗：**台／美股、日／週／月／分線；2y 先到、10y 先到、2y 失敗、10y 補全失敗、FinMind 失敗、背景刷新、A→B→A、多使用端訂閱與個別取消。固定回應下比較最終完整輸出雜湊；原生搜尋操作量首屏及完整畫面。

**完成：**K 線殘餘瓶頸與收益有證據，最終資料一致；回訪不增加非預期 chart 請求。若不能安全改善，列為未處理限制，不將其包裝成提速成果。

### 07 — 正式介面驗收與交接

- 使用選定的日常開發入口重跑空 OPTIONS、十檔庫存／匯率、三十檔觀察、十檔 K 線與暖回訪；與同期有效 before 比較，不能只挑精簡測試頁。

- 完整 gate、既有檔案保護、秘密掃描、來源／serve 身分核對及獨立 Standards／Spec 覆核；保留 P1 的證據身分原則，不重建與本案無關的大型驗收框架。

## 5. 共同執行、停止與回復規則

1. 每票先讀[專案規則](../../CORE_RULES.md)、本 PLAN、當票與直接前置；依 `diagnosing-bugs` 先保留可判紅的迴圈，再作最小修改。本次為規劃，因此沒有假稱已執行該迴圈。
2. TypeScript 每個可驗證批次跑 `npx.cmd tsc --noEmit`；每張改碼票收尾跑 `npm.cmd run gate`，含完整測試、build、金鑰掃描及 package／lock 差異。新來源精確加入追蹤後才作最後金鑰掃描；不得 `git add .`。
3. 依 code-review skill 做獨立 Standards／Spec 雙軸覆核，處理阻擋項後一票一個最終 commit，再更新票面；這是後續實作流程，不是本次規劃的提交授權。若有 merge，依專案規則記 `Code-Review:` trailer。
4. 不裝新 npm 套件，不升級 Node／Vercel／依賴，不改 package／lock、提示詞、模型、供應商、公共領域型別、費率、匯率值／沿用規則、行情日期或金融計算。工具鏈升級若成為必要解法，另列有證據的提案。
5. 既有測試紅燈或需要改金額語意時停止該分支，列「現值／原規則、依據、擬變更及使用者影響」再詢問；不改期望值、不刪測試、不放寬 timeout 或錯誤條件假裝解決。
6. 同一修法連續兩次無效，回到原重現與單變因隔離；不追加更多設定碰運氣。因工具／環境缺口無法驗證，列出已完成、未驗收及恢復條件。
7. 本體五鍵與真帳本不動；正式 App 測試用隔離資料，真 AI 禁止。真行情僅在使用者採用執行範圍後作只讀驗收。
8. 不刪歷史 `.scratch`，不改 `.planning/`、Skills 鏡像或共用規則。執行副本與巨量產物採排除／外置，不能用摧毀證據換取效能。
9. 回復以本案逐票提交與設定備份為單位，按依賴反向處理；先核未提交修改，禁止 `reset --hard`、`git clean` 或遞迴刪除未核實路徑。
