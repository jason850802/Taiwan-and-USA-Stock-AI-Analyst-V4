# 本機 K 線與庫存報價效能修復規格

Status: active — 2026-09-22

本規格採用同目錄 PLAN 的執行順序與限制。目標是降低 localhost 下 K 線與庫存報價的可見等待，同時維持行情、日期、金融計算、快取、請求身分、取消、移除／重加、快照與健檢的既有契約。

## 問題

2026-09-22 診斷已證明兩個可重現的等待來源。第一，provider-free 的 OPTIONS 在原工作區中位數約 6.607 秒，相同產品來源的精簡執行 root 約 1.706 秒；現有證據只足以把差值歸於大型原工作區下的 Vercel dev 準備成本，不能再細寫成每支 request 都掃描特定目錄。第二，台股庫存報價在 Yahoo 價格到達後仍等待 FinMind 中文名稱，名稱完成前 queue 槽位不會釋放，十檔真行情因此把單支等待放大成批次尾端等待。

TypeScript 專案掃描已確認只有 150 個檔案且不含 `.scratch`；2330 同頁回訪亦有 K 線快取命中證據。這兩者不是本案第一修正方向。

## 使用者可觀察的完成狀態

1. 本機 API 空 OPTIONS 的候選環境接近同期精簡對照，且原工作區慢速可重現時，相對 before 有明確下降。
2. Yahoo 已取得有效價格時，庫存列可先顯示價格並釋放價格工作；中文名稱可稍後補入，名稱失敗不使有效價格失敗。
3. 十檔與三十檔量測可分清 runtime、名稱等待與 queue 排程的成本；調整併發上限只有在資料支持時才另行決定。
4. K 線以「搜尋到第一批有效 K 線可見」及「必要 context 完整」兩個時間點驗收，不能用 HTTP 完成時間替代畫面時間。
5. 正式 App 在桌面與窄版下維持搜尋、換週期、回訪、強制更新、移除／重加、快照與健檢失效邊界。

## 硬性正確性契約

- 固定上游輸入下，最終行情、交易日、OHLC、成交量、指標、篩選與金融計算輸出一致。
- 名稱補入前後只允許名稱與顯示完整度改變；名稱不能帶回舊價格、交易日、錯誤狀態或新的 `fetchedAt`。
- force、同 key 去重、舊請求失效、移除／重加、卸載、快取發布世代與匯率旁路維持。
- 本體資料五鍵內容在隔離驗收前後逐值一致；測試只使用合成 symbol／id，不寫真帳本。
- 真 AI 禁止；行情供應商、提示詞、模型、公共領域型別、費率、匯率數值／沿用規則、交易日與金融公式不變。
- package 與 lock 不變；既有測試／snapshot 不為本案改期望值。

## 效能門檻

### 空 OPTIONS

Yahoo chart 與 FinMind 分路由比較。每個服務啟動先保存一次冷啟動，之後至少五個交錯配對暖回合，並至少兩次獨立服務啟動。候選暖中位數需不高於同期精簡對照的 `1.25 倍 + 250 ms`；若同期原工作區仍重現慢速，候選相對原工作區暖中位數還需至少降低 50%。所有樣本必須 204；逾時、漏列與錯誤均算失敗。

若新啟動原工作區已與精簡對照同速，需記錄「舊慢速未重現」，不能拿歷史 6.607 秒要求本輪硬減 50%。此時仍可完成名稱阻塞修復，但本機根因修復不得宣稱已驗證。

### 庫存名稱阻塞

固定回應控制器讓 Yahoo 價格已完成而台股名稱保持 pending。正式 hook 必須在名稱未釋放時顯示有效價格，並讓後續價格工作取得 queue 執行機會。另驗名稱稍後補入、失敗、逾時、新價先到舊名稱後到，以及移除／重加與卸載。

### 真行情與固定行情

同期原基準仍重現慢速時，十檔真行情的「首個有效報價」與「全部有效報價＋匯率」三個配對批次中位數各至少降低 40%，逐列成功率不可下降。固定十／三十檔另外保存首檔、全部、排隊、HTTP 峰值、名稱補齊與匯率完成。失敗解除 loading 只算 settled，不算成功。

### K 線

量「送出搜尋→第一批有效 K 線可見」、「必要 context／完整歷史完成」與 API TTFB。回訪需另記 chart 請求數，搜尋 API 與名稱 API 分開計數。

## 執行順序與條件分支

1. 固定基準、可判紅量測與資料保護。
2. 單變因排除非產品目錄，分別驗證 Vercel 與 Vite 行為。
3. 只有第 2 步仍未達本機門檻時，建立可維護的精簡 API 執行目錄；若第 2 步已達標，本步以「證明不需實作」結案。
4. 解耦庫存價格與名稱，三槽先保持不變。
5. 重量十／三十檔，再決定是否需要另提 queue 上限調整。
6. 分類 K 線剩餘等待，只修有證據且不改行情語意的瓶頸。
7. 以日常開發入口完成正式介面、gate、雙軸覆核與結果交接。

## 證據身分與量測規則

- 每一正式 run 使用新的 run-id；輸出目錄已存在時拒絕覆寫。
- 每組結果綁定 commit、實際來源雜湊、未提交來源狀態、量測工具雜湊、Node／Vercel 版本、來源 root、origin、PID、port、時區與快取模式。環境變數只保存名稱／是否存在，不保存值或秘密雜湊。
- 既有診斷資料只作歷史證據與工具反例；正式 before 必須是本輪 fresh run。
- 固定行情以可手動釋放的 Promise 控制完成順序，不用數毫秒 sleep 猜競態。
- 小樣本只報原始值、中位數與範圍，不報 p95 或 SLA。
- 真行情先列請求預算；遇 429、持續 5xx 或逾時即停止該批並保留結果，不密集重試。

## 停止規則

既有測試紅燈、需要變更金額／匯率／沿用窗等金融語意、同一修法連續兩次無效、或缺乏可判紅重現時，停止該分支並保存目前證據。不得以放寬 timeout、刪測試、取消工作、漏列、快取命中或失敗快速結束取得較好數字。

## 不在範圍

正式部署效能保證、工具鏈升級、新 npm 依賴、改用其他行情供應商、重做圖表、加大快取容量、修改 tsconfig 收錄範圍、真 AI 品質、真帳本寫入，以及沒有量測依據的長駐 runtime 重寫。

## 完成定義

七張票均依條件分支結案；完整 gate 與 Standards／Spec 覆核通過；最終報告清楚區分本機環境改善、固定資料行為、真上游觀察與正式部署未驗證，並保存可直接重跑的命令與逐票回復方式。
