# 07 — 正式介面驗收、結果報告與回復交接

Status: ready-for-agent
Blocked by: 01, 02, 03, 04, 05, 06
Type: task

本檔為正式票據。依本案共同驗收手冊執行。

## 要交付的結果

以選定的日常開發入口重新驗收整條使用者路徑，整理可核對的 before／after、分支決策、限制、回復與逐票證據，確認本案改善沒有破壞既有行情與庫存契約。

## 實作範圍

- 重跑空 OPTIONS、十檔庫存／匯率、三十檔觀察、十檔 K 線與暖回訪；只與同期有效 before 比較。
- 正式 App 桌面與窄版使用隔離合成資料，驗搜尋、換週期、回訪、強制更新、移除／重加、快照與健檢失效邊界。
- 真上游 hook 與假資料 App 證據分開陳述；真上游不可用時保留未驗收狀態。
- 完整 gate、既有檔案保護、秘密掃描、來源／serve 身分與獨立 Standards／Spec 覆核。
- 最終報告列出每項 before／after、樣本數、時間口徑、成功／429／失敗、採用或未採用分支、未處理限制、啟停／回復命令與逐票提交。

## 驗收條件

- [ ] 所有前置票均 resolved，條件票的未實作分支也有證據結論。
- [ ] 正式介面與固定資料驗收均使用本輪來源身分，沒有混用歷史 before。
- [ ] 本體資料五鍵、快取／匯率／競態／P1／S1 防護均無退化。
- [ ] 完整 gate 與雙軸覆核 OPEN 0，package／lock 與秘密紅線通過。
- [ ] 最終報告明確區分「本機環境已改善」「固定資料行為驗證」「真上游觀察」「正式部署未驗證」。
- [ ] 只清理由本案建立且已核實的服務／臨時秘密；原始證據保留，不推送、不部署、不發版。

## 邊界

任一關鍵門檻、真上游驗收或前置決策仍 OPEN 時，本票保持未完成，不能用 mock 全綠取代使用者症狀驗收。
