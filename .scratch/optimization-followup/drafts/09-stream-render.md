# 09 — 長 AI 報告合併畫面更新

Status: needs-triage
Blocked by: 02
Type: task

本檔為票據草案。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

長報告串流時減少不必要的全文 Markdown 解析，完成後立即呈現完整內容，取消與換股不混入舊報告。

## 實作範圍

- 先掃描實際有串流呈現的入口，固定 100 KiB Markdown／1,000 片段量測現況；包含標題、表格、清單及分段邊界。
- 保持輸入累積文字完整，只合併同一畫面更新週期的顯示提交。優先一個小而共用的顯示邊界，不各入口複製一套排程。
- 完成時立即提交最終全文，不依賴下一個動畫影格；背景分頁恢復後顯示最新內容。錯誤／取消保留內容政策與現況一致。
- 報告身分、股票切換、卸載與重新分析要取消舊畫面工作；02 的請求歸屬不能被顯示排程破壞。
- 若量測證明已有等效合併且無可改善成本，交付證據並保留現況，不能為行數或預定方案硬加一層。

## 驗收條件

- [ ] 原始片段拼接、最終 state、AI 快取及畫面可讀內容一致；Markdown 結構沒有缺字、重複字或順序錯亂。
- [ ] 同一畫面週期收到多個片段時只提交一次常規更新；完成有獨立立即 flush，計數與渲染時間有前後證據。
- [ ] 測過空報告、單片段、快速片段、慢片段、途中失敗、取消、重新分析、換股與卸載。
- [ ] 所有實際串流入口至少 smoke 驗收一次，長報告主路徑做完整假資料瀏覽器驗收。
- [ ] AI 延後載入、提示詞逐位元組鎖、模型設定與請求協定無變更；沒有真實 AI 呼叫。
- [ ] 型別檢查、新增必要行為測試與完整 gate 通過；獨立 code-review：Standards、Spec 均已處置。
- [ ] 證據與提交完成；若無需修改，有可重跑數據支持並明確標示。

## 邊界

不換 Markdown 套件、不改全文為截斷摘要、不減少收到的內容、不改服務端分段。關票後停止，下一票為 10。
