# 02 — 基本面換股、載入與重試正確歸屬

Status: needs-triage
Blocked by: 01
Type: task

本檔為票據草案。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

快速切換股票時，基本面、重試及 AI 狀態都屬於目前選擇的股票，等待期間不會誤讀前一檔數字。

## 實作範圍

- 分清「使用者目前要求的股票」與「已成功取得資料的股票」。用最新請求身分限制成功、錯誤及 finally；需要時傳遞取消，但不能只靠取消保證正確。
- 換股時明確呈現正在載入哪一檔；可以暫留舊內容作背景，但必須標明舊資料並避免以舊資料觸發新股分析。
- 重試使用最後一次失敗的目前請求代碼，不退回前一個成功代碼。快速 A → B → A，同一代碼的不同次請求也要區分。
- AI 生成與基本面載入分開管理；舊股票的完成、錯誤或 finally 不影響目前股票。保留既有每股 AI 結果與再次查閱行為，不改提示詞或 AI 快取鍵語意。

## 驗收條件

- [ ] 新增案例可在修改前重現 A 慢／B 快覆蓋問題，修正後最終代碼、日期及數值只屬於 B。
- [ ] A 已顯示 → B 等待 → B 失敗 → 重試，實際送出的代碼為 B，載入與錯誤回饋可辨識。
- [ ] A → B → A、舊請求先失敗／後成功、元件卸載，均不錯改目前狀態。
- [ ] AI 生成 A 時切 B，A 完成／失敗不覆蓋 B 的報告與 loading；切回 A 的行為符合既有快取契約。
- [ ] 在隔離假資料瀏覽器完成上述操作並記錄實際代碼／數值；服務或純函式測試不能代替此項。
- [ ] 既有 AI 延後載入仍成立；新增行為測試、型別檢查與完整 gate 通過，既有測試零修改。
- [ ] 獨立 code-review：Standards、Spec 均已處置，證據及本票提交完成。

## 邊界

不改財報數據整理、估值、AI 提示詞或快取有效期。不為改善載入提示重設整個基本面頁面。關票後停止，下一票為 03。
