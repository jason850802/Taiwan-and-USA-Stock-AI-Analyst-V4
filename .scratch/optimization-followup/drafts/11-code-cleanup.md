# 11 — 清理重複路徑與補充現況文件

Status: needs-triage
Blocked by: 02、03、04、05、06、07、08、09、10
Type: task

本檔為票據草案。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

前述修正留下的舊分支、重複排程或宣告被安全移除，維護者可找到現況責任與測試入口；避免為了瘦身把功能或保護刪掉。

## 實作範圍

- 重新跑模組引用與未用宣告檢查，檢視本輪被取代的請求、清理、快取與串流路徑；先列候選、用途證據與預期收益，再動手。
- 靜態可到達包含型別引用，不代表每個 export 都用到；相反地，找不到直接引用也不能忽略動態入口、公開 API 或測試用途。
- 優先移除本輪確定無用的實作和重複邏輯。若沒有可安全刪除的項目，記錄證據，不為達數量移除防護。
- 最多抽出一個可獨立測試的小職責，例如行情日期格式轉換；僅在多處重複責任或邊界收益明確時做。不得同票拆行情、圖表與 AI 三大檔。
- 新增當前架構／效能說明，指出資料請求、快取、串流、驗收入口與仍未處理的大檔責任；主 PLAN 增加現況文件連結。歷史快照保留原樣。

## 驗收條件

- [ ] 每個刪除候選有引用／用途查核，沒有刪除活躍功能、測試、snapshot、分析規則或提示詞。
- [ ] 若抽模組，原公開型別與結果不變，既有 callers 不需要理解新內部細節；沒有只轉呼叫的多餘包裝。
- [ ] 分開統計正式程式與測試／工具新增刪除，說明減少的重複責任，不用淨行數作唯一成績。
- [ ] 首屏大小與四組行情輸出／量測符合共同回退門檻，必要 UI 路徑仍通過。
- [ ] 現況文件能引導到實際責任與驗收證據；未改寫歷史規劃或共用規則。
- [ ] 型別與完整 gate 通過；既有測試中的未用 import 不為瘦身順手修改。
- [ ] 獨立 code-review：Standards、Spec 均已處置，證據與提交完成。

## 邊界
