# 06 — 後端 Yahoo 握手共用與失效恢復

本檔為正式票據。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

同一後端執行個體冷啟動時，多個行情請求共用有效的 cookie／crumb 握手；握手失敗或認證失效後可以重試。

## 實作範圍

- 先讀並執行現有後端 Yahoo 行為測試，記錄握手、401／403／429、重試上限與錯誤傳遞的實際契約。
- 同一執行個體共用進行中的握手，cookie 與 crumb 作為同一世代配對使用；不可讓新 crumb 配舊 cookie。
- 處理握手失敗清理及快取失效世代；舊握手晚成功不能把已失效的認證放回，舊請求回來的認證錯誤不能任意清除更新的一組。
- 維持目前合法的重試次數與退避，不透過加大次數掩蓋限流，不把真實 cookie 或 crumb 寫入紀錄。

## 驗收條件

- [x] 冷啟動 10 個並行請求只啟動 1 組握手，取得一致的 cookie／crumb 配對。
- [x] 暖請求沿用現行有效憑證；握手失敗後後續請求可成功，沒有永久 rejected Promise。
- [x] 握手未完成時失效、新舊握手反序完成、舊認證錯誤晚抵達，均由可控制順序的新增測試覆蓋。
- [x] 現有 401／403／429、fallback 與重試次數行為不變；不改既有測試期望。
- [x] 服務端請求鏈以假回應驗證，無真實 Yahoo 壓力測試或秘密輸出。
- [x] 型別檢查與完整 gate 通過；獨立 code-review：Standards、Spec 均已處置，證據與提交完成。

## 邊界

只保證單一執行個體內共用；不增加外部資料庫、跨個體鎖或憑證保存機制。關票後停止，下一票為 07。
