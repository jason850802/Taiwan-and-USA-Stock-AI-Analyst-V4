# 03 — 共用 K 線補全且通知所有有效使用端

Status: ready-for-agent
Blocked by: 01
Type: task

本檔為正式票據。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

使用者快速切離再切回同一檔，仍會收到背景補全；不同使用端共用一次行情請求且彼此取消不干擾。

## 實作範圍

- 先以可控制回應順序重現「第一個使用端過期、第二個使用端加入但未收到補全」。記錄現行短歷史、完整歷史與強制更新的公開回呼契約。
- 將共享網路工作的身分與每個使用端的有效訂閱分開。後加入者須收到適合其需求的結果；只要還有有效使用端，單一取消不得使其他使用端失去結果。
- 保留先 2 年後 10 年的既有分段語意、只需要完整歷史的呼叫端，以及 force 發出新更新的行為。只共享同樣需求的工作，不能讓短歷史冒充完整歷史。
- 成功、失敗、取消後清除進行中狀態與訂閱；舊世代不可覆蓋較新資料。一個使用端回呼出錯時，不得阻止其他有效使用端被通知。

## 驗收條件

- [ ] 兩個一般使用端讀取同一待補全資料，實際網路工作共用，各自收到契約要求的補全且無重複終結通知。
- [ ] A 使用端失效後 B 加入同 key，B 收到補全；取消 B 不影響仍有效的 A，順序交換也成立。
- [ ] A 股慢 → B 股快 → 回 A，畫面最後收到正確 A 歷史深度，不停留舊圖或被 B 回應污染。
- [ ] 分段、完整歷史需求、force 重疊、錯誤後重試均有行為測試；控制回應順序，不用真實延遲猜測。
- [ ] 反覆 100 次加入／退出／結束後，未留下已終結訂閱或 in-flight 項目；證據可由測試生命周期觀察，不為測試公開內部 Map。
- [ ] 四組固定行情完整輸出雜湊一致；假資料瀏覽器實際切股／切頁補全通過。
- [ ] 型別檢查與完整 gate 通過；獨立 code-review：Standards、Spec 均已處置，證據與提交完成。

## 邊界

不改 TTL、歷史範圍、MA 暖機、分析指標、提供商或降級順序。不順便重寫整個行情服務。關票後停止，下一票為 04。
