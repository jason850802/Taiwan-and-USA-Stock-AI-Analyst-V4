# 04 — 庫存報價與匯率 UI 防止舊回應覆蓋

Status: resolved — 2026-09-20
Blocked by: 01
Type: task

本檔為正式票據。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

一般載入與手動刷新重疊時，庫存 UI 只採用最新有效請求，價格、時間標記與匯率不會被晚到的舊結果覆蓋。

## 實作範圍

- 每個股票代碼與匯率建立最新請求歸屬，從發起意圖到成功／錯誤／結束都檢查。已有服務快取保護仍保留，UI 不假設服務已解決畫面競態。
- 保護持股移除、清單變動及卸載；舊結果不能把已移除項目加回。快取命中的直接回填也必須尊重最新身分。
- 保留原有價格、報價日期、取得時間、快取與 force 行為，以及無有效匯率時的現行顯示方式。
- 驗證價格與匯率更新觸發每日快照的既有行為；只修結果歸屬，不重訂何時記帳、損益或缺匯率的數值意義。

## 驗收條件

- [x] 一般請求慢、force 快；及先 force 後一般讀取，依最新有效意圖顯示結果，兩種回應先後順序均覆蓋；後續一般快取讀取不得使尚待完成的強制更新失效。
- [x] 舊成功／新失敗、舊失敗／新成功的狀態不互相污染；不能悄悄改成另一套失敗時沿用價格政策。
- [x] 匯率同樣有兩種回應順序案例，最後顯示及計算輸入值正確，沒有改匯率值、60 分鐘沿用窗或股票行情窗。
- [x] pending 時移除持股、移除最後一檔美股、清空、卸載，無幽靈項目或過期 state 更新。
- [x] 隔離瀏覽器以假持股驗證價格／日期／時間標記與快照相關讀值；不寫入真實資料。
- [x] 型別檢查、新增行為測試、完整 gate 通過；金融行為鎖與既有測試零修改。
- [x] 獨立 code-review：Standards、Spec 均已處置，證據與提交完成。

## 邊界

本票不做請求排隊。若修正需要改缺匯率、損益或快照的金額語意，依根規則攤開現值、依據、擬變更及影響後詢問，不能自行決定。關票後停止，下一票為 05。
