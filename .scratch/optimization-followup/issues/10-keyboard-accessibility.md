# 10 — 視窗焦點與圖示操作可及性

Status: resolved — 2026-09-21
Blocked by: 01
Type: task

本檔為正式票據。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

使用者只用鍵盤也能開啟、操作與關閉共用視窗，焦點不跑到背景，圖示按鈕有明確可讀的操作名稱。

## 實作範圍

- 開啟時記錄來源焦點，設定合理初始焦點；Tab／Shift+Tab 在可見且可操作項目間循環，沒有可操作子項目時留在視窗容器。
- 關閉後還原來源；來源已移除或停用時回到合理且仍存在的控制項，不把 focus 留在卸載節點。
- 如既有流程有疊層，只由最上層處理 Escape／焦點循環；內層關閉回外層，不一次關閉全部。
- 支援動態顯示／停用的內容，保持捲動與點擊背景的既有行為，不新增視窗框架。
- 為圖表指標設定等實際缺名稱的圖示按鈕補繁中可讀名稱；名稱說明動作，有切換狀態時提供對應語意。

## 驗收條件

- [x] 新增、匯入、分析視窗以全鍵盤完成開啟、正向／反向循環、操作、Escape 與焦點返回。
- [x] 視窗開著時，背景控制項不能透過 Tab 取得焦點；初始焦點與關閉後 document.activeElement 有實測紀錄。
- [x] 動態隱藏／disabled、無子控制項、來源按鈕移除，以及實際疊層情境均不失去焦點。
- [x] 長內容可捲動，390×844 與 1440×900 無新增整頁溢出，關閉後背景捲動正常。
- [x] 所有本票涉及的圖示按鈕在可及性樹有明確名稱；沒有以 tooltip 視覺顯示代替必要名稱。
- [x] 型別檢查與完整 gate 通過；實際瀏覽器證據齊全，不把未做的螢幕閱讀器實機操作宣稱已驗證。
- [x] 獨立 code-review：Standards、Spec 均已處置，證據與提交完成。

## 邊界

不重畫 UI、不安裝新套件，不為未存在的任意多層視窗建龐大管理系統。關票後停止，下一票為 11。
