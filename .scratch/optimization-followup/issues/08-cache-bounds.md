# 08 — 可重建快取有界且儲存降級安全

Status: resolved — 2026-09-21
Blocked by: 07
Type: task

本檔為正式票據。依主 PLAN 的共同驗收手冊執行。

## 要交付的結果

使用者大量切股後快取仍有容量界線，近期工作集可重用；瀏覽器儲存失效只影響加速，不破壞操作或投資組合本體。

## 實作範圍

- 完整讀取 07 決策並採用其數值與策略。行情價格／K 線與基本面分辨各自需求，避免為所有快取建通用框架。
- 限制權威記憶體與相關索引／別名的總保留成本。entry 淘汰時其別名同步釋放，不能由旁邊的 Map 繼續保留大資料；session 讀回也必須經過容量檢查。
- 清除過期日期的基本面快取；保留股票與外匯原有 TTL、資料形狀及正規化相容。超大 entry 按已定規則可顯示，但不可使長期快取超標。
- 只操作自己擁有的可重建儲存命名空間；不得清除投資組合、設定、交易、備份或其他應用 key。
- 僅在 07 選擇延後持久化時實作排程，記憶體寫入維持即時；舊排程不可寫回已淘汰或被新值取代的資料，明確處理清空、重載與寫入失敗。

## 驗收條件

- [x] 30／100 檔三輪切換後容量及別名索引符合 07 上限，近期工作集命中符合決策，超大 entry 可正常呈現。
- [x] 正規代碼／別名／session 回填、跨日、淘汰後重抓的公開輸出與日期／數值一致。
- [x] 儲存額滿、拒絕、JSON 損壞與序列化失敗均可退化，畫面可繼續操作；無關 sentinel key 完整保存。
- [x] 若採延後寫入，舊／新寫入反序、清除後 flush、重載邊界均測試；未採用則附 07 的數據理由。
- [x] 前後量測包含記憶體估值、耗時、命中率與請求數，不只報容量下降。
- [x] 既有公開儲存行為若與決策衝突，保留原契約或提出缺口，不修改既有測試綠化。
- [x] 完整行情雜湊一致、型別檢查與 gate 通過；假資料瀏覽器壓力／降級路徑通過。
- [x] 獨立 code-review：Standards、Spec 均已處置，證據與提交完成。

## 邊界

不變更真實使用者儲存格式，不改有效期與金融語意。不做沒有量測支持的 IndexedDB 遷移。關票後停止，下一票為 09。
