# 07 量測方法

本票不修改產品。`profile-server.mjs` 以既有 esbuild 在記憶體中編譯原始服務，僅附加兩種觀測：把原有快取 Map 註冊到測試宿主的閉包，以及包住 `processYahooResult`／`enrichChartData` 計時。對外只回傳聚合數字，正式原始碼沒有新增私有 Map 的出口；探針不改 Map、不替換資料演算法。

來源 SHA-256 在編譯前固定，probe bundle 與量測工具也有 SHA-256；結果寫檔使用啟動時的指紋，不能在測完後改讀新版程式再替舊結果蓋章。`summarize.mjs` 對 14 份完整樣本及故障案例逐份核對，缺一份或來源不符即失敗。

## 固定條件

- 專屬 origin `http://127.0.0.1:4180`，只綁 loopback。開始只清除此測試 origin 的儲存，先寫入七個合成 sentinel；不接觸其他 origin 或真實投資組合。
- 瀏覽器時區必須是 `Asia/Taipei`，不符即停止；全域 Date 固定從 `2026-09-20T04:00:00Z` 開始，基本面第二日明確推進一天。
- 30／100 個合成股票代碼；日線 2,500 棒、週線 520 棒、小時線 1,600 棒。三輪連續讀取，每輪保持相同數值／日期並核對完整輸出雜湊。
- 股票一半為合成美股，一半為名錄缺漏的合成台股。後者特意走裸代碼→後綴的殘餘別名路徑，能觀察同 payload 的兩把 key。空名錄可能被重新查詢，因此 **K 線快取命中**與**所有服務 fetch 次數**分開；不能把額外名錄查詢當成重抓 K 線。
- fetch 邊界直接回傳合成 Response，假延遲 0 ms；計數是服務 fetch 次數，不冒稱實際上游 HTTP。未知應用 API 拒絕，原生 fetch 只用來載入本地測量工具及保存結果。
- 每種規模 sample0 為首次冷頁面，sample1 排除作暖機，sample2～6 為五次完整量測；每頁重新初始化模組與快取。這控制頁面初始狀態，不宣稱能完全消除瀏覽器 JIT／OS 波動。冷頁面與五次中位數、最差值各自保留。

## 指標口徑

`uniquePayloads` 以 Map 的值物件身分去重；`aliases = keys - uniquePayloads`。估值採唯一 entry 序列化後的 UTF-16 字串長度×2，key 成本另外列出；不把別名重算成另一份 payload，也不把此估值叫作真實 heap。Map 桶、物件 header、臨時字串及目前 UI 持有資料不在此估值內。

轉換時間只計真實 `processYahooResult` 與 `enrichChartData` 的同步時間；不將它宣稱為整個服務的唯一成本。`JSON.stringify` 與原生 Storage.setItem 各自計時，包含失敗樣本；完整服務耗時另外列出。為避免探針自身干擾，估算大小盡量沿用寫入時的序列化長度，輸出雜湊計算使用原生 stringify，不加入產品序列化耗時。

long task 是整個測試頁面觀測，可能包含探針、雜湊及回報成本，只列觀測數，不用它單獨判定產品儲存停頓。沒有可靠 heap 歸因，故不報真實 cache heap。

## 故障與超大資料

故障場景分別模擬 quota 與 Storage 拒絕、注入壞 JSON、將循環物件送入公開快取寫入，以及取得 20,000 棒的超大行情。核對公開回傳與測試頁面的實際標的／棒數／末價，所有 sentinel 逐位元不變。這是量測宿主的資料可用性驗證；08 另須完成正式 App 的壓力／降級驗收。

## 校正紀錄

`precheck/` 保留第一輪量測工具校正資料。該版 `hits` 的意思是「完全沒有任何 fetch 的呼叫」，空名錄查詢會使它低估 K 線命中，不能拿來當最終 cache hit rate。修正後重新量完整樣本，加入 `chartRequests`、`callsWithoutAnyFetch`，最終統計只讀本層 `profile-*.json`。校正數據沒有移作修正版的結果。
