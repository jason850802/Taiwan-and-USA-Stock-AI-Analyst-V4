# 07 容量決策：供 08 直接採用

數值的機器可讀版本是 `capacity-decision.json`。1 MiB＝1,048,576 bytes。以下都是快取保留資源的工程預算，不修改資料新鮮度或金額意義。

## 量測依據

五次正式樣本的資源數量一致。30 檔三週期加最新價／匯率共有 121 個唯一 payload、166 把 key，其中 45 個別名；payload 大小估值 **344,940,664 bytes**。100 檔則為 401 份、551 把 key、150 個別名，估值 **1,149,801,854 bytes**。同一物件的別名沒有重算 payload。

單份日線最大為 **6,245,216 bytes**；20,000 棒的超大行情為 **50,065,242 bytes**。不設容量時超大 entry 也長期保留。30／100 檔完整循環的第二、三輪 K 線命中率皆 100%，這是高保留成本換來的結果，不能只把容量下降當成無代價改善。

基本面 100 檔當日資料只有 **649,200 bytes**、key 約 5,000 bytes；跨日後累積 200 份、1,298,400 bytes。保留一百檔當日資料合理，保留已不會被當日 key 讀到的前一日資料沒有加速價值。

## 記憶體與索引

| 快取 | bytes 預算 | 個數預算 | 單項上限 | 決策理由 |
|---|---:|---:|---:|---|
| 行情（K 線＋最新價） | **128 MiB** | **160 個唯一 payload、320 把 key** | **8 MiB** | 可容納最後十檔三週期約 115 MB，再加一百個很小的最新價；一般 2,500 棒日線在單項門檻內，20,000 棒超大項目不長留 |
| 基本面 | **2 MiB** | **128 個 entry** | **256 KiB** | 保留一百檔當日工作集並有合理餘裕；日期過期即清理，不累積多天 |

bytes 使用「唯一 entry 的 JSON UTF-16 字串長度×2，加各 key 的 UTF-16 長度×2」。物件 header、Map 桶、臨時資料與 UI 已持有的結果不在此估值內，所以這不是整個頁面或 heap 的 128 MiB 承諾。個數上限另限制索引及 metadata 數量。

行情以 payload 物件身分為單位維護最近使用順序；讀任何別名都更新該 payload 的最近使用。容量淘汰必須同步移除其全部記憶體 key／別名及索引，不能把大物件留在旁邊的 Map。替換同一 key 為新結果時，舊物件的別名與舊持久化失效，避免舊資料由另一名稱復活。session 回填也走相同容量檢查。

超過單項門檻、循環等不可序列化值，或單項加 key 已超預算時，本次服務仍回傳結果讓畫面呈現，但不放入長期快取。不得為了符合容量而截短歷史、改棒數、日期或指標。

## 持久化

| 命名空間 | 總預算 | key 上限 | 單項上限 |
|---|---:|---:|---:|
| `quote_cache_v1:` | **4 MiB** | **64** | **2 MiB** |
| `tw_fund_` | **1 MiB** | **128** | **256 KiB** |

預算包含該層 key 與 payload 字串。兩層獨立；大日線／小時線可留記憶體但不放入 session。近期週線與小報價可在 F5 後重用；不承諾每一檔大日線都能跨重新整理保留。瀏覽器實際 quota 可能更小，這些數值不是保證分配量，失敗仍須安全退化。

維持同步 best-effort 寫入。原生 setItem 單次最差樣本為 30 檔 **22.3 ms**、100 檔 **31.4 ms**；序列化最差分別 **13.0 ms／15.4 ms**。這些是大型 entry 的成本，足以支持限制大型持久化；目前沒有「延後寫入比有界同步寫入更好」的對照證據，因此 **不採用延後持久化**，不引入待 flush 工作、卸載遺失或舊值反序寫回的新機制。08 必須重測，不能因此宣稱同步成本已經消失。

`storage` 計時僅是原生 setItem 嘗試，沒有包含 quota 失敗後枚舉／刪除 key 等外圍成本。服務總時間另有量測，不用兩者相加或相減假裝精確歸因。

quota 時只淘汰自家命名空間，最多重試一次，仍失敗略過持久化；拒絕存取與壞 JSON 一律可退化。既存 session key 沒有新存取時間欄位，初始順序使用掃描順序，此後在本頁讀寫時更新 LRU；不改原有儲存格式來儲存 metadata。

基本面每次讀寫先清非今日 key；跨日後舊請求完成只回覆原等待者，不把前一日 cache 再放回。保留原股票／匯率沿用窗、快取 key 格式、正常化與 force 契約。

## 08 的量化驗收

重跑同一 30／100 檔、三週期三輪場景。所有保留 payload／key 與 bytes 必須在上述上限內，超大 20,000 棒仍可返回／呈現。最後十檔三週期在先讀一次後立即再訪，K 線請求數應為 0；一百檔當日基本面第二、三輪仍可命中。完整 30／100 檔循環可能因 LRU 產生重抓，必須列出實際命中率、請求數及耗時，不把代價藏起來。

另用公開行為測試及正式 App 瀏覽器驗證別名、session 回填、跨日、quota／拒絕／JSON 損壞／序列化失敗；投資組合、交易、快照、設定與無關 sentinel 全保留。產品只動可重建快取責任，不導入跨快取萬用框架。
