# Sol 執行與驗收手冊

適用於本改善 01～12。入口為 [PLAN](../../PLAN.md)，需求為 [spec](spec.md)。票據內的條件加上本手冊，才構成完整驗收。

## 一票的完成流程

1. 確認模型為 GPT-5.6 Sol，讀專案規則、當票、前置票。宣告本次只做哪一票。
2. 記錄固定比較點、Git 狀態、已有使用者修改與本票可動範圍。未開始的票改 claimed；接續票先讀其已完成證據。
3. 新增可重現失敗的行為測試，或建立可重跑的效能／鍵盤場景。先記錄修改前結果。
4. 完成最小修改，型別檢查與局部測試；必要時進行假資料瀏覽器操作。
5. 完整 gate、相對於固定基準的 package／lock 零差異、既有測試／snapshot 零修改。既有測試若紅，遵守專案停止規則，不改測試綠化。
6. 依 code-review skill 作兩軸獨立覆核。明確提供固定比較 commit、完整 diff、spec、當票、規則與驗收證據。未提交的新檔不能漏在覆核之外。
7. 修正發現並驗證受影響內容；程式又改過則重跑最終 gate，覆核修正處。保存一票一個最終提交。
8. 關票記錄日期與證據。若只是程式寫完、缺實際驗收或覆核，仍維持 claimed 並記錄缺口。

若有 merge commit，依根規則附 `Code-Review:` trailer，分列 Standards／Spec 處置；沒有 merge 就不為了 trailer 強造 merge。純文件票依規則可免程式 gate，但本票若驗收的是程式候選，仍需對候選跑 gate。

## 基準與回復

- 01 先逐檔列出既有變更來源，保留追蹤／未追蹤檔案。以差異備份與 SHA-256 清單保障可回復；只收錄本案原始碼、測試、工具與文件，不複製環境秘密、瀏覽器資料、個人投資組合或依賴目錄。
- 備份不能取代對原工作區的保護；不得 reset、clean 或 stash 使用者的無關修改。備份中的程式不必重複提交入庫，只提交必要清單與證據摘要。
- 01 的基準提交要涵蓋已確認屬本最佳化的第一輪成果；比對保存前後正式程式雜湊，證明未偷偷變更候選。
- 建議工作分支前綴 `codex/`。先保存基準再考慮 worktree；若繼續原工作區，逐票維持固定比較點即可，不要求為隔離而丟棄修改。
- 回復以指定本票 commit 的反向修改為單位，先確認後續票依賴與工作區差異。不得用回到舊 HEAD 的方式移除第一輪或使用者其他成果。

## 共同驗證指令

在專案根目錄執行，Windows 使用 `npm.cmd`／`npx.cmd`；每條分開執行並檢查退出碼，不用 PowerShell 5.1 不支援的 `&&`。

```powershell
npx.cmd tsc --noEmit
npm.cmd run gate
node scripts/benchmark-market-data.mjs
node scripts/measure-initial-bundle.mjs --skip-build --json
node scripts/audit-source-usage.mjs
```

完整 gate 已包含型別、全測試、建置與金鑰掃描，不需無理由再重跑同一輪 build。首屏工具的 `--skip-build` 僅在 dist 確實對應當前原始碼時使用。執行有成本的完整效能矩陣集中在 01、相關效能票、12，不要求每次文案變更重跑。

gate 金鑰掃描若顯示降級，要照實記錄原因與未涵蓋範圍，不印出秘密、不為了檢查把秘密複製到前端。即使 gate 綠燈，也另外比對 package／lock 對本票起點及 01 的差異。

## 測試邊界與工具

- 服務競態：沿用現有 Vitest 與假 fetch，控制回應順序／錯誤，不以毫秒延遲推測並行。
- UI／hook：建置後使用 [既有假資料站](../optimization-2026-09-18/preview-fixtures.mjs) 起步，按票擴充所需資料／串流路由；新版本與場景記錄於本案證據。所有應用 `/api` 攔截，未定義路由明確拒絕，禁止悄悄轉送真實服務。
- 假資料站只綁本機，使用隔離 browser context 或專屬 origin 的測試儲存。開始記錄 port／pid，結束只停止自己啟動的程序；不終止使用者的其他 Node 程序。
- 不已有瀏覽器驗收能力時可交接操作步驟，但該項記「未驗收」。不得用純函式測試代替實際鍵盤焦點或 hook 整合證據。
- 真實開發環境若有需要，按專案 start-dev skill；假資料驗收不用真實 AI／行情端點。

## 效能量測規格

每次記錄：候選 commit／工作區雜湊、Node 與瀏覽器版本、資料集、固定時鐘／時區、冷暖快取、網路假延遲、量測方法與原始結果。前後使用相同條件，一次暖機後至少五次取中位數；首次冷啟動另列，不能混平均。

| 情境 | 固定輸入 | 記錄指標與判定 |
|---|---|---|
| 首屏 | 相同正式 build 設定 | 初始 JS raw／gzip；相對 01 若增長超過 5%，必須定位並處理，不能悄悄通過 |
| 行情處理 | 沿用四組假行情資料 | 完整輸出 SHA-256 相同；中位數若回退超過 10%，再做一批五次判定是否穩定退步，確認退步要定位修復 |
| 庫存批次 | 1、10、30 檔，固定回應延遲、失敗一檔 | 實際峰值、請求數、首檔可見與全部完成時間；限制峰值可能拉長全量時間，須一起回報，不能只展示一個有利數字 |
| 重疊更新 | 30 檔尚未完成時更新兩次 | 同一庫存載入範圍的峰值 ≤ 3（含匯率）；最後更新完成，舊回應不能蓋回 |
| 快取 | 30／100 檔、日／週／小時、重複三輪、跨日 | 唯一 payload 與 key 數、估算保留 bytes、序列化／儲存耗時、重訪命中與請求數；估值不冒充真實 heap |
| 長報告 | 同一份 100 KiB Markdown，1,000 個片段，逐字合併相同 | 收到片段數、畫面提交次數、渲染耗時、完成延遲；同一畫面週期多片段合併，最終全文完全一致 |

5%／10% 是本計畫的回退調查門檻，不是宣稱現有量測精度或真實網站 SLA。避免在 Vitest 以真實毫秒門檻製造不穩定測試。

07 必須交付可被 08 直接採用的數值：容量上限、計數單位、近期使用工作集、溢出規則、超大 entry 規則、淘汰順序、是否延後持久化。依 30／100 檔三輪結果選定並記錄理由，不能只寫「之後再研究」。容量是工程資源預算；如果需要改資料新鮮度或金額口徑才須另問使用者。

## 最終 UI 矩陣

| 路徑 | 必驗內容 |
|---|---|
| 市場分析 | 搜尋、清空、鍵盤選股、日／週／小時切換、縮放、均線設定、行情失敗／重試、背景補全 |
| 基本面 | A 慢 B 快、B 失敗重試、已有 A 等 B、AI 生成中換股／回切、未預先載入 AI 模組 |
| 庫存 | 空清單、30 檔假持股、重疊更新、單檔失敗、移除持股、匯率未完成／過期回應、既有快照行為 |
| AI 報告 | 合成長串流、正常完成、途中失敗、取消、切股、重新分析；全文／Markdown 表格完整 |
| 共用視窗 | 新增／匯入／分析；Tab／Shift+Tab 循環、Escape、返回焦點、背景不可鍵盤進入；實際有疊層時驗最上層 |
| 尺寸 | 1440×900 桌面與 390×844 窄螢幕；記錄 viewport 和 scrollWidth，長表格可局部捲動，不應拖寬整頁 |

畫面比對至少記下股票代碼、日期、假資料價格及載入／錯誤狀態；截圖輔助，不單憑肉眼宣稱數字相同。正常情境無非預期 console error；故障注入錯誤列於獨立清單。

## 證據與回報格式

正式執行後建立 `evidence/NN/`。必要摘要用 Markdown，量測用 JSON，保留可重跑入口；不收錄真實秘密、cookie、個資或庫存資料。

每票最少保存：固定基準／候選、重現方法、前後結果、測試與 gate 摘要、UI 操作及實際讀值（適用時）、雙軸覆核、差異分類、剩餘限制。

交接回覆固定六項：

1. 本票結果：完成／未完成，以及使用者看得到的改變。
2. 修改範圍：動了哪個責任、保留了哪些重要行為。
3. 驗收：實際跑的測試與數據，附證據連結。
4. 覆核：Standards、Spec 各自發現／處理／剩餘數。
5. 提交與限制：提交雜湊、未驗收部分、如何回復。
6. 下一票編號；到此停止，等待使用者指定繼續。
