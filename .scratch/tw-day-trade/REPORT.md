## 4. 批次 code-review（`main..HEAD` 全 diff，Standards＋Spec 雙軸）

### Spec 軸：**無發現**

逐條對過 spec.md 的「實作決策」與 ADR-0003 的七項決策，另外實地查核了三個
「設計保證」而非只讀規格：

- **三個預估端一律一般稅率**：`calcTwSellFeeAndTax` 的全部 7 個產線呼叫端逐一查過
  （統計卡 1、明細表 3、歷史回推 3），**沒有任何一個傳第三參數**；只有賣出引擎傳。
- **對帳單匯入產出 `undefined`**：重播引擎自建 trade 物件，不經賣出引擎。
- **舊備份回灌後為 `undefined`**：備份模組搬的是整把 key 的原始 JSON（無欄位白名單），
  已實現帳本的 store decode 也是 `raw as TradesFile` 的直通轉型——新欄位不會在
  存／讀往返中被吃掉。此點另有實證：DOM 驗證是在 **preview 重啟＋整頁重載後**
  才看到徽章，代表旗標確實走完了 localStorage 往返。

### Standards 軸：**1 筆發現，已修**

| # | 發現 | 處置 |
|---|---|---|
| R-01 | 理由文案原用 `switch`，但本專案 tsconfig 非 strict、也沒開 `noImplicitReturns`。日後 `DayTradeReason` 新增代碼時 switch 漏接**不會編譯錯**，只會靜默少顯示一行理由——而那行理由正是這個勾選框存在的意義 | 改成 `Record<DayTradeReason, (lot) => string>`（缺 key 必紅）。**已用探針實測**本專案 tsconfig 下會報 TS2741，不是憑印象。行為零變動。commit `53e2871` |

其餘 Standards 項目通過：2 空格縮排、單引號、繁中註解（**已機械掃描新增行，
零簡體字**）、camelCase／PascalCase、無無關檔案重排、零新依賴。

### 實作期翻出的疑義（依掛機規則取保守解，已記入 findings.md）

- **F-03**：賣出股數欄位空白時判定回 `odd-lot-sell`。取保守解——勾選框停用且不勾
  （＝一般稅率、寧多課稅），顯示文字換成中性的「輸入賣出股數後判定」（照代碼直譯
  會顯示「零股不得當沖」，對一個只是還沒填完的欄位是誤導）。純函式與引擎一行未改。
- **F-04**：賣出股數超過持有股數時勾選框仍可能顯示「符合現股當沖」。未修——
  該筆賣出根本送不出去（引擎擋下、預覽顯示錯誤、確認鈕鎖住），不會造成任何錯帳。

既有的 **F-01（brokerDiscount 死欄位）／F-02（無交易時間資料）依票 04 範圍外規定不處置。**

### 一處對 spec 的刻意偏離（請使用者過目）

spec 寫「`assessDayTrade` 是唯一新增的公開函式」。實作另外 export 了
**`DAY_TRADE_HARD_GATE_REASONS`（常數陣列）** 與 `DayTradeReason`／`DayTradeAssessment`
兩個型別。理由：硬閘清單同時被「引擎夾制」與「UI 停用勾選框」使用，各寫一份等於
把同一條規則放在兩個地方漂移。export 的是**資料不是第二個判斷函式**，
spec 的本意（判定邏輯只有一個來源）沒有被破壞。
