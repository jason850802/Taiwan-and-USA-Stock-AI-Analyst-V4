# Spec — 台股賣出支援現股當沖減半證交稅（0.15%）

Status: ready-for-agent
來源：grill-with-docs 2026-07-29 九題拍板＋接縫覆核（硬閘／軟閘表使用者確認）；
邊界決策見 ADR-0003；詞彙見 CONTEXT.md「台股現股當沖」節；待裁決項見同目錄 findings.md

## 問題陳述

使用者實際會做台股現股當沖，但 App 的賣出流程只認一般交易稅率（個股 0.3%）。
每次當沖賣出，帳上證交稅都是實付的兩倍，已實現損益被低估——碰錢的數字錯，
帳本就失去對帳價值。同時三條紅線不可動：既有測試案例零修改、備份 schema 不升版、
對帳單匯入一律取帳單實付數字。

## 解法

賣出視窗自動判定這筆是否為現股當沖（同批買進日＝賣出日 ∧ 台股個股 ∧ 雙邊整張），
自動勾選、可覆寫；勾選時證交稅按 0.15% 計。當沖是「賣出動作」的屬性，不是批次的
屬性——庫存資料模型零變更，判定與算稅全在既有兩個純函式接縫內完成，帳本留三態痕跡。
預估類的三個顯示端（統計卡／明細表／歷史回推）一律維持一般稅率不感知當沖。

## 使用者故事

1. 作為只做多的當沖使用者，我要賣出視窗自動判定並勾選「現股當沖」，讓減半稅額不靠我記得勾。
2. 作為使用者，我要自動判定的規則可預測（該批買進日＝賣出日、台股個股、持有與賣出股數皆為 1000 整數倍），讓我能預判系統行為。
3. 作為使用者，我要在勾選框旁看到判定理由（判到／沒判到分別因為什麼），讓我一眼確認系統看到了什麼，而不是只看到一個勾好的框。
4. 作為使用者，我要能手動取消自動勾選（處置股、未簽當沖同意書、券商未沖銷成功），讓帳跟券商對得起來。
5. 作為使用者，我要在系統沒判到但實際是當沖時能手動勾起來（該批買進日是舊資料沒填或填錯；或該批是「整張＋零股」合併建檔、持有股數非整張），讓漏判不會讓我多記一倍的稅。
6. 作為使用者，當賣出股數含零股（非 1000 整數倍）時，我要勾選框被鎖死並提示「拆成兩筆賣出」，讓我不會把整筆錯誤減半（零股不得當沖）。
7. 作為使用者，同一批當天分次整張賣出時（早上沖一張、下午再沖一張），我要每筆各自判定、各自成立。
8. 作為使用者，賣一般 ETF／債券 ETF 時我要看到停用的勾選框與「ETF 當沖不適用減半」說明，讓這條稅法結論固化在介面上。
9. 作為使用者，賣美股時我不要看到任何當沖控制項，因為美股無證交稅、勾了沒有意義。
10. 作為使用者，勾選當沖後我要預覽的證交稅立即按 0.15% 重算並標示，讓確認前就看到入帳金額。
11. 作為使用者，我要已實現帳本的當沖賣出帶「沖」標記，讓日後對帳能分辨這筆按哪種稅率課。
12. 作為使用者，我要對帳單匯入的賣出維持帳單實付稅額、旗標一律「不知道」，因為那些數字是券商算好的、系統不猜。
13. 作為使用者，我要舊備份檔照常回灌（schema 不升版），讓這功能不作廢我手上任何一份備份。
14. 作為使用者，我要統計卡／明細表／歷史曲線的預估賣出成本一律按一般稅率估，讓還沒賣的部位維持保守估計、數字不因跨日跳動。
15. 作為使用者，我要改動賣出股數或日期後，先前的手動覆寫失效、回到自動判定，讓覆寫不會黏在已經不成立的輸入上。
16. 作為使用者，我要當沖只影響證交稅、手續費照舊 0.1425%，因為折讓是券商商業條件不是稅法。
17. 作為維護者，我要既有測試案例零修改由設計保證（新參數全 optional、預設＝現行為），不靠實作時小心。
18. 作為 AI agent，我要票面可冷啟動（讀票即可動工），讓換窗紀律不折損交付品質。

## 實作決策

### 資料模型（最小增量）

- `RealizedTrade` 新增 optional 欄位 `isDayTrade?: boolean`，**三態語意**：
  `true`＝這筆按當沖課稅（0.15%）；`false`＝明確按一般交易課稅；
  `undefined`＝不知道／不適用（舊資料、美股、對帳單匯入的所有賣出）。
- `PortfolioItem` **零變更**（ADR-0003 決策 1：當沖是賣出動作的屬性，不是批次的屬性）。
- **不升備份 schema 版本**（紅線）：備份模組的版本檢查是嚴格不等即整包拒收，
  升版＝使用者手上所有既有備份檔報廢。optional 欄位是唯一合規的擴充法，
  舊備份回灌後該欄位為 `undefined`＝三態中本來就有定義的一態。

### 費率與算稅

- 當沖個股稅率常數 `0.0015` 進費率設定檔（twFeeRates），與三檔一般稅率並列；
  計算式與 rounding 仍留費稅模組（設定與計算分離，沿該檔既有原則）。
- 費稅模組兩個函式各加一個 optional 參數、預設維持現行為：
  `getTaxRate(symbol, isDayTrade?)` 與 `calcTwSellFeeAndTax(value, symbol, isDayTrade?)`。
- 減半稅額的正典公式＝**稅率替換、單次 floor**：`floor(value × 0.0015)`。
  全程只有一次 floor，禁止任何中間 rounding（如先算一般稅額取整再除二）。
  手算案例：321,500 × 0.0015 = 482.25 → 482（一般交易為 964）。
- **非個股一律忽略旗標**：`getTaxRate` 對 `etf`／`bond-etf` 收到 `isDayTrade: true`
  仍回傳 0.001／0。「只有個股減半」（ADR-0003 決策 3）鎖在最低層，不靠 UI 紀律。
- 手續費完全不動：不加參數、不改費率、不碰折讓。

### 判定純函式（唯一新增的公開函式，掛在既有賣出引擎模組上）

- 賣出引擎模組 export `assessDayTrade(lot, sharesSold, sellDate) → { eligible, reason }`。
  不吃價格——判定不依賴價格，UI 在價格欄空白／報價缺失時也要能畫勾選框。
- `reason` 是**代碼不是文案**（文案由 UI 映射，純函式不持有顯示字串）：
  `'eligible' | 'not-tw-stock' | 'etf-not-eligible' | 'odd-lot-sell' | 'odd-lot-holding' | 'date-mismatch' | 'no-buy-date'`
- 判準（全部成立才 `eligible`）：台股個股 ∧ 賣出股數為 1000 整數倍 ∧
  該批持有股數為 1000 整數倍 ∧ 該批 buyDate ＝ 賣出日期。
- reason 優先序固定（硬閘先於軟閘，UI 據此顯示唯一一條理由）：
  `not-tw-stock` → `etf-not-eligible` → `odd-lot-sell` → `no-buy-date` → `date-mismatch` → `odd-lot-holding`。

### 硬閘／軟閘（覆寫的方向性，使用者拍板）

| reason | 覆寫成 true | 依據 |
|---|---|---|
| `odd-lot-sell`（賣出股數非整張） | **不可（硬閘）** | 零股賣單現實中不可能沖銷；賣出股數是此刻親手輸入的事實，沒有「資料舊了」的藉口。混合賣出（如 1500 股）的正確做法＝拆成兩筆賣出（1000 勾當沖、500 不勾），UI 要提示 |
| `etf-not-eligible`／`not-tw-stock` | **不可（硬閘）** | ETF 不在減半條文射程；美股無證交稅 |
| `date-mismatch`／`no-buy-date` | **可（軟閘）** | buyDate 是儲存的中繼資料，可能沒填或填錯（Q4 拍板保留覆寫的本意） |
| `odd-lot-holding`（持有非整張、賣出是整張） | **可（軟閘）** | 手動建檔可能把「整張買＋零股買」併成一批（如 1137 股）；當日整張買 1000、整張賣 1000 是合法當沖，但自動判定看持有股數會漏判 |

### 賣出引擎整合

- `SellInput` 新增 optional `isDayTrade?: boolean` 三態：`undefined`＝請引擎用
  `assessDayTrade` 自動判定；`true`／`false`＝覆寫。
- 有效旗標＝**夾制（clamp）後**的 `(input ?? 自動判定結果)`：硬閘不過（非台股個股、
  或賣出股數非整張）一律強制 `false`。**夾制不拋錯**——與 `getTaxRate` 忽略非個股
  旗標同一套縱深防禦；UI 擋第一層、引擎夾第二層、稅率函式守第三層。
- 台股賣出一律在 `trade.isDayTrade` 記錄有效旗標（`true`／`false`）；
  美股不寫該欄位（`undefined`）。`SellResult` 形狀**零變更**（既有測試的解構不受影響）。
- 稅額走 `calcTwSellFeeAndTax(value, symbol, 有效旗標)`；已實現損益公式不變
  （`gross − sellFee − sellTax − costBasis`，`sellTax` 自然反映減半）。

### UI（賣出視窗）

- 台股個股：顯示勾選框「現股當沖（證交稅減半 0.15%）」，**預設值＝自動判定結果**，
  旁附理由文字（判到：顯示判準成立；沒判到：顯示對應 reason 的說明）。
- 台股 ETF／債券 ETF：勾選框**顯示但停用**＋「ETF 當沖不適用減半，仍為 0.1%／免稅」。
- 美股：**完全不顯示**任何當沖控制項。
- `odd-lot-sell`：勾選框停用＋提示「零股不得當沖；若實際為整張當沖＋零股賣出，
  請拆成兩筆賣出」。
- 覆寫黏性：使用者手動改過勾選後，**任何股數或日期的變動都把覆寫重置回自動判定**
  （沿買入表單 feeTouched 的既有模式）。
- 勾選時預覽的證交稅列標示「（當沖 0.15%）」；預覽與入帳走同一條純函式路（既有原則）。
- 勾選框的狀態與理由由 UI 直接呼叫 `assessDayTrade` 取得（不依賴預覽是否成立）；
  預覽與入帳把勾選框當下的值傳給引擎。

### 帳本 UI

- 已實現帳本中 `isDayTrade === true` 的列顯示「沖」徽章；`false` 與 `undefined`
  一律不顯示標記（不區分「明確一般」與「不知道」——顯示層不放大三態）。

### 明確零變更清單

- 對帳單匯入：不從稅額反推旗標（反推＝猜，違反 D-06），產出的賣出一律 `undefined`。
- 三個預估端（統計卡／明細表／歷史回推 estSellCosts）：一律一般稅率。
  持有過夜在定義上就不是當沖；且旗標不在批次上，這三條路徑拿不到它（設計保證）。
- 歷史帳不回改：舊 `RealizedTrade` 維持原稅額與 `undefined`；要修單筆走既有的刪除重記。
- 不做落日日期閘門：減半期限（現行至 2027-12-31）只入註解與 CONTEXT.md。

## 測試決策

- **接縫**：只在既有兩個純函式模組的測試檔加案例（費稅模組測試檔＋賣出引擎測試檔）；
  不寫元件測試（專案慣例：node_modules 外零個 .test.tsx）。
- **好測試＝只測可觀察行為**：回傳金額、記錄在 trade 上的旗標、reason 代碼；
  不測內部實作。手算對數案例先手算、再寫斷言（費稅模組既有檔的風格）。
- **既有案例零修改由設計保證**：新參數全 optional 且預設＝現行為，既有斷言原封不動；
  新增案例（addition）不受紅線限制。
- 費稅模組新增案例（手算對數）：
  - `getTaxRate` 個股帶 `true` → `0.0015`；ETF／債券 ETF 帶 `true` → 仍 `0.001`／`0`（縱深防禦）。
  - `calcTwSellFeeAndTax` 當沖手算對數：650,000 → 稅 975（一般 1,950）；
    321,500 → 稅 482（482.25 floor；一般 964）；500 → 稅 **0**（0.75 floor；一般 1
    ——當沖小額稅可為 0，同案鎖 `sellFee` 仍為 max(1,…)＝1，即旗標恆不影響手續費）。
  - 期望值一律先手算再寫斷言；三案皆為 0.0015 直乘、單次 floor。
- 賣出引擎新增案例：
  - `assessDayTrade` 七種 reason 各至少一案（含優先序案例：同時零股賣出＋日期不符 → 回 `odd-lot-sell`）。
  - `buildSellResult`：`undefined` 自動判定成立 → 稅減半＋`trade.isDayTrade === true`；
    軟閘覆寫 `true`（date-mismatch）生效；硬閘覆寫 `true`（odd-lot-sell）被夾制
    （稅照一般＋記 `false`）；覆寫 `false` 生效；美股 trade 無 `isDayTrade` 欄位；
    同批同日兩筆整張分次賣出各自成立。
- **驗收**：收尾 `npm run gate` 全綠；既有案例零修改；UI 驗證量數字不靠肉眼
  （預覽稅額與手算值比對）。
- **findings 紀律**：實作中翻出的可疑行為 append 進同目錄 findings.md
  （已預埋 F-01 brokerDiscount 死欄位、F-02 無交易時間資料），一律不順手修。
