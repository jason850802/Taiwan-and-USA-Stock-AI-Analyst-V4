# 01 — 報價服務接上行情快取基座（含匯率旁路與同步偷看）

Status: resolved（2026-08-13；實作 `00ea7cd`，code-review 修正 `c586345`）
Blocked by: 無（本案第一張）

## 目標

讓**報價服務**（回傳 `{ price, name, date }` 的那支最新價函式，與 K 線那支是不同
函式）接上既有的**行情快取基座**，沿用同一套 TTL 政策；匯率代碼走 60 分鐘旁路；
另提供同步偷看與強制更新兩個能力，供票 02 消費。**本票純服務層，不碰任何元件。**

## 規格依據

spec.md「一、報價快取（服務層）」節；CONTEXT.md「報價快取與健檢重跑」節的
**報價快取**／**沿用窗**／**強制更新**三個詞；偵查證據見 RECON.md 第一章。

## 範圍

做（行情快取基座）：
- 新增**報價快取鍵**產生函式：獨立命名空間（形如 `latest|<代碼>`），代碼經
  trim ＋轉大寫正規化。**不做名錄預解析、不寫記憶體別名。**
- 新增**報價新鮮度判定**純函式，收「寫入時刻、現在時刻、代碼」三個參數：
  - 代碼以 `=X` 結尾（不分大小寫）→ 固定 60 分鐘短窗，**完全不看市場開收盤**。
  - 其餘 → 委派既有的市場感知判定（市場歸屬用基座既有的分類函式）。
  - 60 分鐘常數要有具名常數與註解，寫明「外匯是 24 小時市場，故不套市場時段」。
- **既有的市場感知判定演算法一行不動**（檔內註解已明寫「演算法順序即語意，勿重排」）。

做（報價服務）：
- 函式簽章加**選用**參數 `{ force?: boolean }`。為真時跳過讀取直接抓。
- 未強制時先讀快取：命中且新鮮 → 直接回，**零網路請求**（連台股的中文名查詢
  也一併省掉）。
- 抓取成功後回寫快取，**閘門：價格 > 0 且為有限數才寫**。無效值與失敗一律不寫。
  寫入的 entry 要把「只享短 TTL」旗標明確設為 `false`（基座的驗證函式要求它是布林）。
- 回傳型別 additive 加「實際抓取時刻」欄位（ms epoch）：現抓＝寫入當下的時刻、
  命中＝快取 entry 的寫入時刻。**此欄位不進快取 payload**，由 entry 推導。
- 新增**同步**偷看函式：命中且新鮮才回值（含抓取時刻欄位），否則回 `null`。
  回傳一律**淺拷貝**，不把快取內的物件參照交出去。

不做：
- K 線那支函式（`getStockData`）的任何變更——鍵、SWR、預解析全部零觸碰。
- 抓取層、解析邏輯、中文名查詢、匯率查詢路徑的任何改寫。
- 新增 localStorage key 或任何新的儲存層（沿用基座的記憶體＋sessionStorage）。
- TTL 數字參數化。
- 任何元件、hook、UI 檔案。
- 網路分支的 mock 測試（屬 CONTEXT.md 的「首批外」）。

## 紅線

1. **快取鍵命名空間不得與 K 線相撞。** 記憶體層是單一 Map，K 線存 `{info, data}`、
   報價存 `{price, name, date}`；用 `<代碼>|<週期>` 形狀當鍵會讓 K 線快取解析出
   報價物件。命名空間必須讓兩者**不可能**產生相同字串。
2. **無效價格不得進快取。** 下市／冷門標的可能回 `NaN`／`undefined`，寫進去會毒
   一整天（沿用窗最長到下一交易日開盤）。
3. **既有測試零修改。** 本票全部是 additive（新函式、選用參數、回傳新增欄位）。
   既有測試紅燈＝語意變更的訊號，**停下來問使用者，不准改期望值**。

      期望值先手算再寫斷言：
  - [x] 匯率旁路：`USDTWD=X` 寫入後 59 分鐘 → 新鮮；61 分鐘 → 過期。
  - [x] 匯率旁路**不受市場時段影響**：同一組（寫入、讀取）時刻，一次落在美股盤中、
        一次落在美股盤後，判定結果相同。
  - [x] 旁路真的生效：同一組時刻下，匯率代碼與一般美股代碼的判定結果**不同**。
  - [x] 盤中 10 分鐘窗：台股盤中寫入，9 分鐘後讀 → 新鮮；11 分鐘後讀 → 過期。
  - [x] 沿用窗：台股週五收盤後寫入、週六讀 → 新鮮。
  - [x] 跨越開盤即過期：台股週五收盤後寫入、下週一開盤後讀 → 過期。

  - [x] 鍵命名空間：報價鍵與同代碼的 K 線鍵（`<canon>|1d` 形狀）**不相等**。

- [x] `npx tsc --noEmit` 0 錯誤；報價服務的既有兩個呼叫端**一行不改**仍可編譯

## 給接手方的提示

- 判定函式放**基座**而非報價服務：純函式、可直測，且 TTL 政策集中一處。
  基座檔頭已宣告「模組頂層絕不觸碰 sessionStorage/window」的純模組守則，
  新增內容要遵守同一條（才能在 Node 下直接 import 測試）。
- 本票結束後，行為上**使用者看不出任何差別**（庫存頁還沒接線）——這是預期的。
  唯一可觀察的變化是同一分頁內連續呼叫報價服務時的網路請求數。
