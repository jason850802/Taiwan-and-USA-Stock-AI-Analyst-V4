# 03 — 健檢重跑：結果視窗內重新健檢 ＋ 重試失敗子集

Status: ready-for-agent
Blocked by: 無（與 01／02 平行，不碰同一批檔案）

## 目標

補上單檔健檢的重跑入口——**成功與失敗都能重跑**，且按下後**留在結果視窗內**
轉圈、就地換成新報告；另加一顆「重試失敗（N）」把失敗子集**一次送進同一次
LLM 呼叫**，成功的檔位不重打。

## 規格依據

spec.md「三、健檢重跑（互動層）」節；CONTEXT.md 的**重新健檢**詞條
（與「全部健檢」「重試失敗」的分工）；偵查證據見 RECON.md 第三章。

## 背景（讀碼前先知道）

現況是「只要該檔有健檢結果就換成徽章」，所以**不論成功或失敗，單檔重跑的能力
整個不存在**——不是只有失敗才沒得重跑。徽章點下去開的是結果視窗，
視窗 footer 目前只有一顆「關閉」。

## 範圍

做（健檢 hook）：
- 批次 handler **參數化**成可接受「目標代碼清單」：
  - 未傳 → 沿用「全部持股」的現行語意（**「全部健檢」行為零變更**）。
  - 有傳 → 只跑該清單，且**必須先與現有持股取交集**（失敗後被刪掉的檔位
    不得再送進去）。
  - 交集後為空 → 直接返回，不打 LLM。
- 對外 additive 導出「目前失敗的檔位清單」（狀態為錯誤、且仍在持股中），
  供庫存頁決定按鈕的出現與數字。

做（庫存頁）：
- **結果視窗的開啟條件改為「該檔有健檢結果就開」**，不再要求報告內容非空。
  現行條件會在重跑瞬間因報告被清空而讓視窗自己彈掉。
- **視窗內容分態**：載入中顯示轉圈與「分析中…」文字；其餘照舊渲染報告。
- **視窗 footer 加「重新健檢」**（載入中時 disabled），沿用既有的**單檔健檢
  handler**，不新增任何分析路徑。成功與失敗一律可按。
- **工具列加「重試失敗（N）」**：僅當失敗檔位數 > 0 時出現，N 即該數字；
  批次進行中 disabled；點擊時把失敗清單傳給批次 handler。
- **【地雷，必改】** 「全部健檢」按鈕目前是 `onClick={批次 handler}`，React 會把
  click event 當第一個參數傳進去。handler 一旦參數化，event 就會被當成目標清單
  → 「全部健檢」靜默壞掉。**必須改成 `onClick={() => 批次 handler()}`。**

不做：
- **持股表零變更**（重跑入口在視窗內，儲存格的渲染分支一行不動）。
- 世代守衛的結構（見紅線）。
- 兩支失敗文案函式、決策解析、切段 fallback 階梯、併發上限的任何改寫。
- 健檢結果的持久化／跨頁存活（維持 unmount 即失）。
- 失敗徽章的顏色語意（列在 spec 的範圍外）。
- 報價快取相關的一切（票 01／02 的事，本票不碰那些檔案）。
- 元件測試（專案慣例不寫）。

## 紅線

1. **世代守衛不得動結構。** 單檔與批次共用同一個 per-symbol 單調遞增 ref，
   是「重疊飛行時較早起跑者的落地結果不得覆蓋較晚起跑者」的唯一保證
   （hook 檔頭已有警語）。參數化批次 handler 時，守衛的建立、比對與早退
   邏輯**照抄**，不得改寫成別的形狀。
2. **「全部健檢」的行為零變更。** 未傳參數時走的路徑必須與現在逐字等價。
3. **既有測試零修改。**

## 驗收

**自動化**
- [ ] `npm run gate` 全綠（本票無新增單元測試——健檢 hook 屬元件層，
      專案慣例不寫元件測試；驗收以 DOM 實測為準）。

**DOM 實測（不靠肉眼判讀，讀 DOM 文字與 Network／console）**

前置：起 dev 環境（`start-dev` skill），庫存頁至少 3 檔持股。

- [ ] **成功後可重跑**：對一檔跑健檢至成功 → 點徽章開視窗 → footer 有「重新健檢」
      → 按下 → **視窗不關**、內容變成載入中 → 跑完就地換成新報告，
      且該檔徽章更新。
- [ ] **失敗後可重跑**：製造失敗（例如暫時停掉後端）→ 開視窗看到錯誤說明 →
      按「重新健檢」→ 視窗不關、轉圈；恢復後端後再按一次 → 成功換成報告。
- [ ] **載入中不可重複按**：載入中時「重新健檢」為 disabled 狀態。
- [ ] **重試失敗子集**：讓批次健檢有 ≥2 檔失敗 → 工具列出現「重試失敗（N）」
      且 N 等於實際失敗檔數 → 按下後 **只有那 N 檔轉圈**，已成功的檔位
      徽章文字**逐字不變**（證明沒被重打）。
- [ ] **一次 LLM 呼叫**：上一步進行時，Network 面板中 AI 分析請求為 **1 筆**
      （不是 N 筆）。
- [ ] **刪除後不殘留**：某檔失敗後把它從庫存刪掉 → 「重試失敗（N）」的 N 減一；
      按下不報錯、console 零紅字。
- [ ] **全部健檢未壞**：按「全部健檢」→ 所有持股都進入載入中（證明參數化沒被
      click event 汙染）。
- [ ] 全程 console 零紅字。
- [ ] 收尾 `code-review`（雙軸 Standards＋Spec），merge 帶 `Code-Review:` trailer。

## 給接手方的提示

- 「重新健檢」不需要新的分析路徑：既有的單檔 handler 已經會把該檔設成載入中、
  重跑、寫回結果，世代守衛也已就位。本票的重點是**視窗不要在那一瞬間彈掉**。
- 失敗清單建議以既有的健檢結果 map 與持股清單推導（memo 化），
  不要另存一份 state——兩份會漂移。
- 製造「資料取得失敗」的最省事作法是停掉後端；製造「分析失敗」則是讓 AI
  呼叫失敗。兩種失敗的文案不同，兩條都值得各按一次重新健檢。
