# 02 — 庫存頁接線：零閃爍帶值、強制更新、報價時間

Status: ready-for-agent
Blocked by: 01

## 目標

讓**庫存報價 hook** 消費票 01 的同步偷看與強制旗標：切回庫存頁時第一個 render
就有數字（**零閃爍、零網路請求**），「更新報價」改為真的強制重抓，工具列加一行
「報價幾點更新」讓快取可被信任。

## 規格依據

spec.md「二、庫存頁接線（元件層）」節；CONTEXT.md 的**強制更新**詞條；
偵查證據見 RECON.md 第二章。

## 範圍

做（庫存報價 hook）：
- 報價 state 與匯率 state 的**初始值都改用 lazy initializer 同步偷看快取**。
  報價：對目前持股的每個代碼偷看，命中者直接以「已載入、無錯誤」的形狀入座。
  匯率：偷看匯率代碼，命中就直接帶價（消掉「預設匯率先閃一個錯的台幣數字」）。
- 全抓函式加**選用**參數 `{ force?: boolean }`：
  - 未強制時，命中且新鮮的代碼**直接落值、不進網路**；未命中才真的抓。
  - 強制時，全部走網路（把旗標透傳到報價服務）。
  - 匯率同一套規則。
- 報價資料型別 additive 加「抓取時刻」欄位，從報價服務的回傳原樣帶入。

做（庫存頁）：
- 「更新報價」按鈕改為**強制更新**。
- **【地雷，必改】** 該按鈕目前是 `onClick={全抓函式}`，React 會把 click event 當
  第一個參數傳進去。加參數後 event 會被當成選項物件 → 強制更新靜默失效。
  **必須改成 `onClick={() => 全抓函式({ force: true })}`。**
- 「更新報價」旁新增一行小字報價時間：
  - 取所有**已載入報價中最舊的**抓取時刻（不是最新——使用者要問的是
    「我看到的數字有多舊」，取最新會被單一檔位拉高而誤導）。
  - 同日顯示 `HH:mm`、跨日顯示 `MM/DD HH:mm`，皆為本機時間、24 小時制。
  - 沒有任何已載入報價時**整行不顯示**（不要顯示空白或占位符）。
  - 文案：`報價 <時間> 更新`。
  - **格式化抽成純函式**（收「抓取時刻、現在時刻」兩個參數），以便單測。

不做：
- `App.tsx` 的分頁掛載方式（維持條件渲染／unmount）。
- 報價 state 上提。
- 報價服務、行情快取基座的任何再修改（票 01 已定案）。
- 每列各自顯示報價時間。
- 每日快照 hook、歷史曲線、持股表、健檢的任何變更。
- 元件測試（專案慣例不寫）。

## 紅線

1. **每日快照的數字必須零變化。** 快照日期取自每檔報價自帶的交易日欄位，
   而沿用窗內市場沒有交易、快取值與重抓值必然相同。本票不得改動快照 effect
   的 deps、debounce 或守衛。若實測發現快照數字有變，**停下來問使用者**。
2. **點擊 handler 的參數地雷**（見上）。
3. **既有測試零修改。**

## 給接手方的提示

- lazy initializer 只在 mount 時跑一次——這正好就是我們要解的情境（切頁＝重新 mount）。
  持股增刪造成的 symbol 集合變動仍由既有 effect 負責，那條路徑的行為不變。
- 「命中直接落值」與「未命中才抓」要在同一個迴圈內分流，不要先無條件設載入中
  再判斷——那樣閃爍會回來。
- 台股收盤後測「切頁往返零請求」最容易觀察；盤中測會受 10 分鐘窗影響，
  若剛好跨過 10 分鐘邊界而看到請求，**那是正確行為**，不是 bug。
