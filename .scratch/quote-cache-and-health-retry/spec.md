# Spec — 報價快取與健檢重跑

Status: ready-for-agent
來源：grill 九題拍板 2026-08-13（拍板紀錄見文末）＋偵查 RECON.md（同目錄，含檔案行號證據）；
詞彙見 CONTEXT.md「報價快取與健檢重跑」節。**不開 ADR**（理由見文末）。

## 問題陳述

兩個各自獨立、但都出在「庫存頁重複做無謂的事」的痛點：

1. **健檢失敗後沒有退路。** 庫存頁按下健檢，若分析失敗，使用者看完錯誤原因後
   只有一顆「關閉」。更嚴重的是偵查發現：健檢儲存格的邏輯是「只要有結果就換成
   Badge」，所以**不論成功或失敗，單檔重跑的能力整個不存在**，只剩「全部健檢」
   批次一條路。批次失敗時尤其難受——12 檔有 3 檔被限流，要嘛開三次視窗沒得按，
   要嘛整批重打（連 9 檔成功的也重花一次 LLM 費用）。

2. **切頁回來就重抓報價。** 庫存頁是條件渲染，切走即整棵樹 unmount，切回來
   必然重跑一次全抓。台股早就收盤、價格一整晚不會變，畫面卻每次都把所有列
   閃成「載入中」再打一輪網路。使用者實際體感是「明明收盤了卻還一直抓」。

根因不在庫存頁，在服務層：`getLatestPrice` **完全沒有快取**，而同一支
`services/yahoo.ts` 裡的 `getStockData` 早有一套兩層快取與已拍板的市場感知
TTL（盤中 10 分鐘／收盤後沿用到下一交易日開盤），`getLatestPrice` 只是沒接上去。

## 解法

**報價快取修在服務層、健檢重跑修在互動層，兩者互不相干。**

- 報價服務接上既有的行情快取基座，沿用同一套 TTL 政策（零新演算法），
  另給匯率一條 60 分鐘的旁路（外匯是 24 小時市場，套股市時段是語意錯）。
- 再提供一支**同步**的快取偷看函式，讓庫存頁在 mount 的第一個 render
  就直接帶值——回頁面零閃爍、零請求。
- 「更新報價」改為強制繞過快取，並在旁邊標示報價時間，讓快取可被信任。
- 健檢的重跑入口放在結果視窗內（成功／失敗都給），另加一顆只重跑失敗子集的
  批次按鈕。

**不動 `App.tsx` 的掛載方式、不上提 state、不新增 localStorage key。**

## 使用者故事

1. 作為使用者，健檢失敗時我要在看完錯誤原因的同一個視窗裡按「重新健檢」，
   不必關掉視窗再想辦法找入口。
2. 作為使用者，按下重新健檢後我要**留在原視窗**看它轉圈、跑完就地換成新報告，
   不要視窗自己彈掉、也不要我再點一次才看得到結果。
3. 作為使用者，健檢**成功**後我也要能重跑（隔天再看、或盤中價格變了想重算），
   不必為了一檔去按「全部健檢」。
4. 作為使用者，批次健檢有幾檔失敗時，我要一顆「重試失敗（N）」把那幾檔
   **一次送進同一次 LLM 呼叫**，成功的檔位不要重打。
5. 作為使用者，台股收盤後我在庫存頁與其他頁之間來回切換，價格要**直接就在那裡**
   ——不重抓、不閃「載入中」，因為市場根本沒有新資料。
6. 作為使用者，同樣的道理要**台美股一視同仁**：美股收盤後切頁回來也不重抓。
7. 作為使用者，我想要最新價時按「更新報價」，它必須真的去抓（不能被快取擋掉）。
8. 作為使用者，我要在工具列看到「報價幾點更新」，才能分辨「價格沒動」是市場
   沒動還是快取卡住。
9. 作為使用者，美股的台幣市值不要在切回頁面時先閃一下用預設匯率算出的錯數字。
10. 作為維護者，每日損益快照、已實現帳本、歷史曲線的數字必須**零變化**——
    快取只影響「何時去拿」，不影響「拿到什麼」。

## 實作決策

### 一、報價快取（服務層）

**TTL 政策沿用，零新演算法。**
- 一般代碼：沿用 `isQuoteCacheFresh`（盤中 10 分鐘／收盤後沿用到下一交易日開盤）。
- **匯率代碼（`=X` 結尾）走 60 分鐘固定短窗，不套市場時段。** 理由：外匯是
  24 小時市場，套美股時段會讓台灣整個白天匯率定死在清晨 5 點的值，而它會流進
  美股台幣市值、健檢成本換算與每日快照的 TWD 口徑。
- 判定邏輯放在**行情快取基座**（政策模組）而非報價服務，理由：純函式、可直測，
  且 TTL 政策集中一處。

**快取鍵獨立命名空間（紅線）。** 形如 `latest|<正規化代碼>`。
基座的記憶體層是**單一 Map**，K 線存的是 `{info, data}`、報價存的是
`{price, name, date}`；鍵撞到 `<canon>|<interval>` 會讓 K 線快取解析出報價物件。

**不做名錄預解析、不寫別名。** 報價服務目前把代碼原樣交給抓取層，不像 K 線那樣
先把裸台股碼解析成 `.TW`／`.TWO`。維持原樣（網路行為零變化），鍵就以呼叫端傳入的
代碼正規化（trim ＋ 轉大寫）為準。後果：`2330` 與 `2330.TW` 會是兩份快取——
持股資料每檔只有一種寫法，無實害；為此加別名不值得。

**寫入閘門：`price > 0` 才寫快取。** 下市／冷門標的可能回 `NaN`／`undefined`
（已記於 CONCERNS.md），這種值寫進去會毒一整天。失敗與無效值一律不寫，
下次自然重抓。

**強制更新**：報價服務加 `{ force?: boolean }`，為真時跳過讀取直接抓、抓完照樣回寫。

**同步偷看**：新增一支同步函式，命中且新鮮才回值、否則回 `null`。
基座的讀取本來就是同步的（記憶體 → sessionStorage 都同步），不需要新機制。
回傳一律**淺拷貝**，不把快取內的物件參照交出去。

**報價時間**：報價服務與偷看函式的回傳additive 加一個「這筆資料實際抓取的時刻」
欄位——現抓就是當下、命中就是快取寫入時刻。此欄位**不進快取 payload**（由 entry
的寫入時刻推導，避免兩份時間漂移）。

**儲存層沿用**：記憶體＋sessionStorage 兩層，前綴不變，**不新增 localStorage key**
——因此 CONTEXT.md 的「本體資料／可重建資料」分類完全不用改。已知連坐行為：
K 線大 entry 撐爆 sessionStorage 配額時，基座的回退會清光同前綴 key（含報價）；
記憶體層不受影響，只有 F5 之後少一層，可接受。

### 二、庫存頁接線（元件層）

- **初始 state 直接帶快取值**：報價與匯率兩個 state 都用 lazy initializer
  同步偷看快取。切頁回來的第一個 render 就有數字，零閃爍；匯率有值也順帶
  消掉「預設匯率先閃一個錯的台幣數字」。
- **抓取迴圈跳過命中檔**：命中者直接落值不進網路；未命中或強制更新才真的抓。
- **「更新報價」傳強制旗標**。
- **【地雷】兩顆工具列按鈕的 handler 形狀**：目前是 `onClick={函式}`，React 會把
  click event 當第一個參數傳入。函式一旦加參數（強制旗標／目標清單），
  event 就會被當成該參數 → 功能靜默失效。**加參數的同時必須改成 `onClick={() => fn(...)}`。**
  這條同時適用於本節與健檢節。
- **報價時間標示**：工具列「更新報價」旁一行小字。取所有**已載入報價中最舊的**
  抓取時刻——使用者要問的是「我看到的數字有多舊」，取最新會被單一檔位拉高而誤導。
  同日顯示 `HH:mm`、跨日顯示 `MM/DD HH:mm`（本機時間）；沒有任何已載入報價時整行不顯示。
  格式化抽成純函式以便單測。

### 三、健檢重跑（互動層）

- **結果視窗的開啟條件改為「該檔有結果就開」**，不再綁 `fullResult` 非空。
  現行條件在重跑瞬間會因 `fullResult` 被清成空字串而讓視窗自己彈掉。
- **視窗內容分態**：`loading` 顯示轉圈與「分析中…」；其餘照舊渲染報告。
- **視窗 footer 加「重新健檢」**（`loading` 時 disabled），沿用既有的單檔健檢
  handler，**不新增分析路徑**。成功與失敗一律可按。
- **工具列加「重試失敗（N）」**：僅當有失敗檔位時出現，把失敗子集
  **一次送進同一次 LLM 呼叫**。作法是把批次 handler 參數化成可接受目標清單，
  未傳則沿用「全部持股」的現行語意（＝「全部健檢」行為零變更）。
- **目標清單必須與現有持股取交集**：失敗後被刪掉的檔位不能還被送進去。
- **世代守衛不得動**：單檔與批次共用同一個 per-symbol 遞增 ref，是重疊飛行時
  「較早起跑者不得覆蓋較晚起跑者」的唯一保證。參數化批次 handler 時，
  守衛的建立與比對邏輯照抄，不得改結構。
- **持股表零變更**：重跑入口在視窗內，儲存格的渲染分支一行不動。

## 測試決策

- **接縫**：行情快取基座新增測試檔（純函式，唯一有自動化覆蓋的一票）＋
  報價時間格式化的純函式測試。**專案慣例不寫元件測試**，票 02／03 的驗收走
  DOM 實測。
- **基座目前零測試覆蓋**（偵查已確認），而本案正要讓報價顯示依賴它的 TTL 判定。
  票 01 補上的是**我們即將依賴的那幾條分支**的行為鎖，不是整支的完整稽核：
  - 匯率旁路：`=X` 代碼在 59 分鐘內新鮮、61 分鐘後過期，且**不受市場開收盤影響**
    （同一組時刻分別在盤中與盤後判定，結果相同）。
  - 一般代碼確實走市場時段規則（同一組時刻下匯率與個股判定**不同**——
    這條是旁路真的生效的證明）。
  - 盤中 10 分鐘窗（9 分鐘新鮮／11 分鐘過期）。
  - 收盤後沿用：台股週五收盤後寫入、週六讀 → 新鮮。
  - 跨越開盤即過期：台股週五收盤後寫入、下週一開盤後讀 → 過期。
  - 寫入時在盤中、讀取時已收盤 → 過期（資料缺當日尾盤）。
  - 快取鍵命名空間與 K 線鍵**不相等**（撞鍵紅線的機械證明）。
- **時間一律以參數注入**（基座的判定函式本來就收 `now`），不碰系統時鐘、
  不用假時鐘套件。期望值先手算再寫斷言。
- **既有案例零修改**（紅線）：本案只做 additive 擴充（新函式、選用參數、
  回傳新增欄位），既有行為不變是設計保證。既有測試若紅燈＝語意變更的訊號，
  **停下來問使用者，不准改期望值**。
- **驗收**：每票收尾 `npm run gate` 全綠；UI 驗證量數字不靠肉眼（讀 DOM／
  Network 面板），不靠截圖判讀；merge 帶 `Code-Review:` trailer。
- **findings 紀律**：實作中翻出的可疑行為 append 進同目錄 `findings.md`，
  不順手修。

## 範圍外

- `App.tsx` 的分頁掛載方式（維持條件渲染／unmount，本案不碰）
- 報價 state 上提到 `App.tsx`（拍板否決）
- K 線快取（`getStockData`）的任何行為變更
- TTL 數字參數化（盤中固定 10 分鐘，沿用現行政策；要改是另一案）
- localStorage 層／跨瀏覽器重啟的報價存活（sessionStorage 足以覆蓋切頁與 F5）
- 裸台股碼與 `.TW` 後綴共用同一份報價快取的別名機制
- 健檢失敗徽章的顏色語意（目前失敗顯示中性色，與成功的「續抱」不易一眼分辨；
  非本次需求，看不順眼列 findings 另議）
- 每列各自顯示報價時間（拍板取工具列單行）
- 健檢結果的持久化／跨 session 存活（維持 unmount 即失，本案只解報價）
- `getLatestPrice` 網路分支的 mock 測試（CONTEXT.md 定義的「首批外」）

## 拍板紀錄（2026-08-13，九題九答）

1. 重跑範圍：**失敗＋成功都能單檔重跑**（偵查揭露成功後同樣沒得重跑）。
2. 重跑後視窗行為：**留在視窗內轉圈→就地換新結果**；開啟條件一併改。
3. 批次重試：**要**，失敗子集一次批跑，成功的不重打 LLM。
4. 修復層級：**服務層**（報價服務接上行情快取基座）；元件層與狀態層兩案否決。
5. 匯率 TTL：**獨立 60 分鐘短窗，不套市場時段**。
6. 回頁面閃爍：**不允許**，同步偷看快取直接帶初值。
7. 報價時間：**要**，工具列一行小字（每列各自顯示案否決）。
8. 盤中 TTL：**10 分鐘，沿用現行政策**（不快取案、2~3 分鐘案皆否決）。
9. 票的切法：**3 張**（服務層快取 → 庫存頁接線 → 健檢重跑）。

## 為何不開 ADR

三項門檻只過了一項半：TTL 政策是既有已拍板決策（`.planning/optimization/PLAN.md`
決策 3）的**延伸適用**，不是新取捨；匯率 60 分鐘旁路確實是新決定，但改回來只是
幾行、可逆性高，一行程式碼註解寫清楚「外匯 24 小時，故不套市場時段」就足夠。
真正需要被未來讀者知道的是**詞彙與紅線**（尤其鍵撞的後果），那屬於 CONTEXT.md。

## 其他備註

- 票據不含檔案路徑與行號（耐久原則）；模組以角色名指認（**報價服務**／
  **行情快取基座**／**庫存報價 hook**／**庫存頁**／**健檢 hook**／**持股表**），
  接手方自行探索；精確位置的偵查快照在 RECON.md（僅供加速，以現況程式碼為準）。
- 依賴順序：**01 → 02**（02 消費 01 的偷看函式與強制旗標）；**03 獨立**，
  可與 01／02 平行開工，互不碰檔。
- 一票一 commit，commit message 繁體中文；`implement` 收尾必跑 `code-review`，
  merge 帶 `Code-Review:` trailer。
- 換窗紀律：每張票建議開新對話冷啟動（讀 spec ＋ RECON ＋ 該票即可）。
- 全案完成後，庫存頁的人工複驗一次做完：切頁往返零請求、更新報價有請求、
  報價時間正確、健檢重跑三個入口都通。
