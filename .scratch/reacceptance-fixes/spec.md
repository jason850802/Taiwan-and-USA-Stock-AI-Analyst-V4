# P1 與 S1 修正規格

Status: claimed

2026-09-21。使用者已採用本規格，01 P1 進行中，02 S1 尚未開始。入口：[PLAN](PLAN.md)；驗收：[acceptance](acceptance.md)。全部正式票結案後才將本規格改為 resolved。

## P1：每一份通過結果都屬於指定執行

**P1-01 — 輪次有兩個層級。** 一次整合驗收使用一份明確的批次清單，列出預期組別與案例；每次假站成功啟動則產生新的唯一 `runId`。清單分別記錄 02、03、04、05-before、05-after 等實際執行，不要求不同伺服器共用同一啟動 ID，也不能把 05 前後版混為同來源。ID 使用既有 Node 能力產生，不新增套件。

**P1-02 — 唯一輸出與明確讀取。** 每次啟站只寫新的獨立目錄，保留舊輪供稽核。驗證、統計與封存以明確批次清單／runId 選檔，禁止掃到所有 `passed` 就合併，也不默默選「最新一份」或 fallback 到舊固定目錄。預期案例清單由工具的場景定義產生，不能由實際找到的檔案倒推完整性。

**P1-03 — 頁面也必須屬於該輪。** 頁面初始載入時，從該份 HTML／bootstrap 回應綁定並固定自己的 runId；結果上傳帶回該 ID。不可到送出時重新抓最新 ID，也不能讓舊頁面延後讀取 metadata 就自動換成新輪。伺服器核對缺失／錯誤／過期 ID 後才接收，拒絕舊分頁向重新啟動的站送結果。來源、工具、候選、建置及案例 metadata 由伺服器核實；不可不經檢查把本輪標籤蓋到呼叫端的舊結果上。

**P1-04 — 案例與檔案完整性。** 各組都要核對預期 case、尺寸、sample、before／after 身分、完整來源與工具集合及雜湊。檔案路徑限制在已核准的本案輸出根，拒絕路徑穿越或覆寫歷史。寫入須避免半份 JSON 被判成功；重複 case 要明確拒絕，或另存 attempt 並在清單明確選定，不可無聲覆蓋使失敗消失。

**P1-05 — 中斷與重啟。** 同一活著的假站可繼續完成該 runId 的缺案；伺服器重啟必須新 runId，該組從新輪完整重跑。批次清單只能明確選一個完整組的執行；不同組可來自不同啟站，不能在同組任意拼接兩輪缺案。本案不新增跨程序續用同 runId 的複雜恢復機制。

**P1-06 — 最後封存不能繞過。** 分組 verifier、05 統計、整合摘要及最終 seal 都保存所選 runId、清單版本與原始檔 hash。缺案、混輪、舊摘要、工具／build 漂移、未完成狀態均須非零退出；不得讀上一輪 `allPassed` 就發布新 PASS。未知 schema 或沒有 runId 的歷史結果不能當成本次新驗收。

**P1-07 — 相容邊界。** 更新實際使用中的入口與 README。舊呼叫方式若沒有足夠的新輪參數，必須明確提示正確命令並拒絕新驗收；不得保留能悄悄漏掉 freshness 的新 PASS 路徑。歷史檔案保持原樣，必要重算用固定提交的舊工具與唯讀副本，不以新工具補寫歷史 metadata。

**P1-08 — 改動效果。** 正常完整一輪仍通過；「漏一案但資料夾有上一輪成功檔」由可能通過變成失敗。runId／hash 是防意外混樣與來源漂移的工程保護，不宣稱可防惡意操作者偽造所有證據。P1 不改股票 App 行為。

## S1：報告綁定已保存的持股輸入版本

**S1-01 — 失效時機。** 使用者的修改經既有表單保存、父層接納為新 `items` 後，才判斷是否失效。輸入框內尚未提交的草稿不自行更改本體或啟動 AI。原有失焦／Enter 保存流程與驗證規則保留。

**S1-02 — 比較的內容。** 按股票建立穩定的持股輸入識別，涵蓋該股票的 lot 組成／身分、股數，以及既有健檢組裝實際讀取的成本來源與購入幣別分支。記錄與比較輸入，不另寫一份成本／損益公式、不新增四捨五入或容差。執行者須先列出實際欄位選取表並用測試鎖定。

目前台股健檢成本取 `totalCost`；美股在 USD 購入且 `totalCostUSD` 存在時取它，否則使用既有台幣成本轉換分支。這些是現行讀取路徑，不是本案的新金融政策；其公式、fallback、單位及精度保持原樣。身份比較的欄位必須反映該路徑，不能只比 symbol，也不能只比畫面已格式化的均價。

新增／刪除／匯入替換另一筆同股票 lot 均須辨認；即使股票代碼一直存在，lot 組成改變仍失效。單純陣列順序改變、相同內容換新物件、未參與健檢的註記／買入日期、顯示幣別或展開收合不得誤失效。沒有任何報告或在途工作的股票維持原「未健檢」狀態。

**S1-03 — 本案不跟隨即時行情自動失效。** 僅報價或即時匯率更新、內容相同的 items 重建，不觸發本次新增的持股編輯失效。手動重新健檢仍照既有服務取當下資料。不要將完整價格／行情陣列納入每次 render 的持股版本，避免報告不斷失效；未來是否訂閱市場變化是另一個產品決定。

**S1-04 — 完成、在途與排定更新都失效。** 相關持股輸入變更時，該股票的請求世代前進、舊影格提交取消、舊結果不再作有效報告。所有非同步邊界、部分片段、完成、錯誤與 finally 清理都必須尊重同一身分；舊工作的 finally 不能清除後來新工作的狀態。由輸入 A→B→A 也不能讓第一個 A 的在途工作復活，故不能僅靠輸入字串相等判斷。

**S1-05 — 清楚且可操作的狀態。** 有舊報告或在途分析的受影響股票改為「持股資料已變更，請重新健檢」。舊全文／決策不得繼續顯示為有效結論；目前已開啟的健檢視窗保留，改顯示提示及可用的「重新健檢」。視窗未開時不得因失效自行彈出；表格提供可辨識的待重跑入口。資料變更不算 AI 服務失敗，也不灌入「重試失敗」計數。

**S1-06 — 單檔與批次共用規則。** 同一股票的單檔與批次必須共享持股版本／請求世代。批次只使受影響股票的舊結果失效，其餘未改股票依既有結果切段與錯誤政策完成；不能清空整份 portfolio 狀態。資料準備期間即已失效的工作，送出 AI 前應檢查並剔除，沒有仍有效輸入時不送出；已送出的共享串流不新增後端中止協定，只隔離過期發布。批次 busy 狀態必須正常結束。

**S1-07 — 手動重跑與快取。** 編輯本身不觸發 AI。使用者選擇重新健檢，才以當前已保存持股啟動新世代。既有按提示詞輸入建立的快取鍵／沿用契約不變，不清空整體 AI 快取、不改提示詞精度以製造 miss。新輸入若依既有序列化恰與有效快取相同，可正常命中；需用明顯不同的假成本確認新組裝輸入正確。

**S1-08 — 原有保護保留。** 股票移除再重加、卸載、StrictMode 重播、單檔與批次重疊、失敗子集重試、完成同步呈現全文及換股隔離皆不可退步。舊股票刪除時仍依原契約清理，不能留下永遠無法關閉的 stale 視窗。新版本資料只保留目前需要的輕量持股識別，不新增無界歷史 payload。

**S1-09 — 修正界線。** 狀態表示可新增失效狀態或等價有型別方案，使用端須同步處理，不能以 `as any` 躲過整合。沒有新增自動分析、金融算法、持股資料遷移、AI 模型或通用快取失效服務。

## 共同交付與證據

兩張票都需修改前精確重現、新增公開行為回歸、最終 gate 與獨立 Standards／Spec。新增測試不修改既有測試的期望。原重新驗收報告維持當時 S1／P1 OPEN，新報告用新提交與新證據記錄 CLOSED；不得回寫歷史造成當時已修的假象。

本規格描述必要行為。01已有修改前紅燈與預檢結果，獨立覆核指出的完整指紋缺口正在修正；預檢不代表最終驗收。P1／S1 仍須各自滿足票面全部條件，才能記錄 CLOSED。
