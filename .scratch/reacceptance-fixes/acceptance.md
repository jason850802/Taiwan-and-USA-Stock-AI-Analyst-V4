## 新 01：P1 的反例矩陣

先在隔離輸出建立「第一輪真實成功、第二輪漏跑」情境，讓舊 verifier 對同來源舊檔仍回成功，新增測試應捕捉這個錯誤而紅燈。不能只用隨便寫出的 `passed:true` 物件假扮真實正常驗收；原歷史 raw 若作種子，只能讀取或複製到測試沙箱。

| ID | 情境 | 修正後必須觀察到 |
|---|---|---|
| P01 | 本輪所有預期案例完整、來源與 build 相符 | 分組 verifier 與封存均 exit 0；manifest 可回到每份 raw。 |
| P02 | 第二輪漏一案，舊輪有同名成功檔 | 本輪缺案，exit 非 0；不讀舊目錄補足。 |
| P03 | 把舊輪真實成功檔放進本輪沙箱 | runId 不符而拒絕，不能被同 source/tool/build 掩蓋。 |
| P04 | 同一組混用兩次啟站、before／after 或不同尺寸 | ID／組別／樣本身分不符而拒絕；05 前後不互相覆蓋 startup。 |
| P05 | 舊頁面跨伺服器重啟後上傳 | HTTP 非成功，無本輪成功檔；頁面不能臨時換取新 ID 自動認領。 |
| P06 | 缺 runId、未知 schema、案例不在預期清單 | 明確拒絕，不走 legacy fallback。 |
| P07 | 來源／工具／建置不符，或刪掉其中一個必要 hash | 集合及值核對失敗；不能只比檔案數。 |
| P08 | 同 case 重複送出，或前次失敗後重試 | 按已文件化的拒絕／attempt 規則處理；失敗不被默默抹掉。 |
| P09 | 半份 JSON、未完成執行、路徑穿越／非法輸出根 | 不產生 PASS；不寫到本案輸出範圍以外。 |
| P10 | 摘要來自舊輪，或 verifier 成功後 raw 被換掉 | 最後 seal 重新核對 run/manifest/raw hash，exit 非 0。 |
| P11 | 同一活站補跑缺案；停止後另起新站 | 前者可依同 run 完成；後者新 run 且不可混入前輪片段。 |
| P12 | 對新驗收使用舊固定目錄命令 | 明確指引新版命令，不能沿不安全路徑宣稱新一輪 PASS。 |

P02／P03／P05／P10 必須各有可觀察拒絕證據；負向測試本身通過，不代表被注入的案例成功。HTTP 原始錯誤、verifier exit code 及封存失敗原因分開列出。

正常路徑最少完成現有 02～05 replay 全部 **88 案**及 05-before **21 份**，保持原行為斷言、來源差異、桌面／窄版及原生市場鍵盤讀值。新版本目錄／身分可改，不能藉此減少原必驗案例。P1 另有負向案例，與這 109 份真實結果分開計數。

## 新 02：S1 的行為矩陣

先用既有兩份原生重現的操作重建 agent 可重跑迴圈，修改前確認「完成後仍舊報告」及「修改後舊在途結果發布」為紅燈。假持股、明顯不同報告標記與可手動釋放的 Promise／串流決定先後，不用任意睡眠推測競態。

| ID | 情境 | 修正後必須觀察到 |
|---|---|---|
| S01 | 同 AAPL／同 lot，已完成後保存 USD 成本100→200，股數10不變 | 顯示需重新健檢；舊判定與全文不再有效；編輯沒有額外 AI 請求。 |
| S02 | 同條件在請求未完成時保存，再釋放舊結果 | 舊部分片段／完成均不回填；舊錯誤也不蓋掉失效或新結果。 |
| S03 | 改股數、台股成本、美股既有不同成本／幣別分支 | 每一種真正相關輸入變更都失效；成本公式與原輸出計算不改。 |
| S04 | 同股票新增第二 lot、刪一筆但仍有其他 lot、匯入替換 lot | 股票未消失仍可識別輸入／組成變更。 |
| S05 | 陣列排序、相同值新物件、未參與健檢欄位、UI 展開／幣別切換 | 報告保持有效；沒有誤失效或多餘 AI 呼叫。 |
| S06 | 未保存的輸入草稿；保存為原值 | 不失效；第一次真正保存不同值才失效。 |
| S07 | 價格／即時匯率單獨更新 | 不因本次新增規則反覆失效；手動重跑依舊使用當時資料。 |
| S08 | 單檔／批次生成中的 A 修改，B 沒改 | A 失效，B 正常完成；批次 busy 可結束，不取消其他股票或誤增失敗計數。 |
| S09 | 取行情或動態 import 尚未完成時修改 | 送 AI 前再次驗身分；過期輸入不送出，全部已失效時零新 AI 請求。 |
| S10 | A100→A200→A100，舊請求反序完成 | 第一個 A100 仍失效，不能因內容恢復而復活。 |
| S11 | 失效後手動重跑，舊單檔／批次最後完成或丟錯 | 只保留新世代結果；舊 finally 不清新狀態；可讀新輸入與報告標記相符。 |
| S12 | 視窗原本開啟／關閉、首次未健檢、失敗狀態再修改 | 已開保留提示與可用按鈕、未開不彈出、未健檢不造假 stale；stale 不算服務失敗。 |
| S13 | 移除重加、卸載、StrictMode、失敗子集重試、全文最後提交 | 原有護欄不退步；無幽靈報告、永久 loading 或懸掛批次。 |

公開 hook／服務案例與正式 App 分開計數。兩個原生症狀 S01／S02、手動重新健檢、新狀態表格／視窗及批次 A/B 至少在 **1440×900 與 390×844** 正式 App 驗證。UI 使用原生輸入與按鈕；開著視窗時的資料變更可用真元件宿主由父層更新合法 props，不繞過焦點鎖操作背景控制項。

保留股票、lot id、前後成本／股數、保存事件、請求數、世代行為可見結果、報告標記／完整內容或 hash、errors、viewport 與 scrollWidth。新增狀態要驗 Tab／Shift+Tab、Escape、來源焦點及兩尺寸不拖寬整頁；不改通用 Modal 實作來繞過失焦。

回歸原有 6 個健檢移除／重加公開案例，以及受影響的單檔／批次串流、取消／重啟／失敗／全文及視窗焦點情境。將實際選用的原案例逐一列入本票 manifest；不可沿用改碼前全來源 fingerprint 當改碼後證據。原有05排程、06握手、08容量等未被改動的功能由完整 gate 與來源零差異保障，不無理由重做所有長時間效能矩陣。

## 證據與新封存要求

新結果在本案 `evidence/<票號>/` 內，按批次清單與 runId 隔離。兩票分別列對應產品／工具版本；P1 產品不變，S1 才改產品。P1 的 109 案是 P1 候選的驗收，不可在 S1 報告中改標成最終產品重跑。任何聲稱對應 S1 最終來源的案例，必須實際用該候選重新執行。

原 `seal-results.mjs` 是舊全矩陣入口；新工具必須阻止它繞過新鮮度檢查。可提供清楚區分的本案 scope／manifest，讓 P1 工具驗收及 S1 專項驗收各自完整；禁止拿本案部分回歸宣稱原 213 案已全部新跑。若選擇重跑完整矩陣，才可以完整數據作此宣稱。

原工具因新狀態或新資料夾確有不相容時，只在新版驗收轉接明確調整，保留舊來源、斷言理由及受影響案例清單。不得覆寫原重新驗收 raw、把 `passed:false` 改成 true，或替舊檔補 runId。歷史未用 import 診斷不順手刪除。

## 獨立覆核與完成門檻

每票各由兩個獨立上下文執行 Standards／Spec；固定比較點、完整 diff、提交列表、未提交新檔、規格及完整新證據全部提供。Standards 同時核對 repo 規則與完整 Fowler 基線；Spec 對照本文和 spec，每項 CLOSED 必須能回到實際 raw／負向結果。作者自查不能替代兩軸。

Reviewer 發現須修正並重跑受影響案例；產品／工具改了，舊 fingerprint 下的結果移入 precheck 保留，不能重新蓋章。只有文案變動且不影響實驗時，核連結與數據一致性即可，不重跑無關 gate。

關票前核對新副本與原工作區差異分類、既有 test/snapshot bytes、package／lock、資料與秘密保護。停止本次確認命令列與建立時間的 PID、關閉自建分頁，核本次使用埠；不停止其他人的 Node 程序。精確記錄工具錯誤，不把歸屬警告誤認為全部工具不可用。

最終結果須包括新兩票的狀態、修正前後差異、實跑命令與退出碼、測試新增數、UI 讀值、P1 反例、run/source/tool/build/raw 綁定、雙軸結果、提交與回復方式。未完成項目逐項列出；S1、P1 只有各自全部要求完成才 CLOSED。
