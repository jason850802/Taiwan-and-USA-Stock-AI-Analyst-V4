# 01 — 股數容差進匯入重播引擎（幻影缺口消滅）

Status: ready-for-agent
Blocked by: —

## 目標

新增股數單位模組（`SHARE_EPS = 1e-6` 常數，含依據註解），匯入重播引擎的缺口閘門
改用容差比較：**`賣出股數 − 池子加總 > SHARE_EPS` 才成立缺口**；容差內視為足額賣出，
FIFO 吃整池。消滅「三批碎股浮點加總比對帳單少 4.4e-16 → 賣出被誤判找不到買進紀錄
→ 整筆略過」的幻影缺口。

## 規格依據

spec.md「股數單位模組」「匯入重播引擎」節；ADR-0004 決策 2；CONTEXT.md「股數容差」。

## 範圍

做：
- 新增 utils 層的股數單位模組：`SHARE_EPS = 1e-6`，註解帶依據
  （券商碎股最小單位 1e-5、浮點累積噪音 ~1e-13，取兩者之間）。
  這是全專案唯一出處，後續票 02（fmtShares）、票 03（賣出引擎）都加在／引用這個模組。
- 匯入重播引擎的缺口判斷改用 SHARE_EPS 容差（只動那一個比較子句與 missing 的成立條件）。

不做：
- 末筆吃餘數分攤、FIFO 排序、費用取帳單實數（D-06）、塵埃批次過濾（1e-9）、
  缺口補值 synthetic lot 路徑——全部零變更。
- 顯示（票 02）、手動賣出（票 03）、匯入紀錄語意（範圍外）。
- 解析器（碎股解析已有行為鎖）。

## 驗收

- 新增行為鎖案例（既有案例**零修改**，期望值先手算再寫斷言）：
  - LITE 實例：池 [1.2048, 1.08896, 0.50824]（buyDate 遞增）＋賣出 2.802 →
    缺口 0、applied.sells 1、trades 3、lots 清空；Σ sharesSold 以 toBeCloseTo(2.802)
    斷言；**Σ grossProceeds／sellFee／sellTax 與帳單總額嚴格相等**（守恆）。
  - 真缺口仍要報：池 [1.0] 賣 2.802 → gap 一筆、sharesMissing ≈ 1.802（toBeCloseTo）、
    該筆賣出略過（既有語意不變）。
  - 界線：差距 2e-6（略大於容差）→ 缺口成立。
  - 反向噪音：池子比賣出多 ≤1e-9 → 賣完後殘餘塵埃批次被既有過濾清掉、lots 為空。
- `npm run gate` 全綠。
- 收尾 `code-review`（雙軸），merge 帶 `Code-Review:` trailer。
