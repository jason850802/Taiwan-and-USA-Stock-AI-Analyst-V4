# 03 — 手動賣出引擎的滿賣／超賣容差（含 clamp）

Status: ready-for-agent
Blocked by: 01, 02

## 目標

手動賣出引擎（buildSellResult 所在模組）的兩個嚴格比較改用股數容差：
超賣擋板放寬為「超出持有股數 ＋ SHARE_EPS 才拋錯」、滿賣判定放寬為
「差距 ≤ SHARE_EPS 即全賣」；容差內的有效賣出股數一律**以持有股數為準（clamp）**
入帳。消滅「手打接近持有數被誤擋」與「留下 2e-16 股塵埃批次」兩種邊緣。

## 規格依據

spec.md「手動賣出引擎」節；ADR-0004 決策 2（clamp 語意）；CONTEXT.md「股數容差」。

## 範圍

做：
- 超賣擋板：`賣出股數 > 持有股數 + SHARE_EPS` 才拋錯；錯誤訊息裡的持有股數
  改用 fmtShares 呈現（不再印噪音浮點）。
- 滿賣判定：`持有股數 − 賣出股數 ≤ SHARE_EPS` → 視為全賣（批次移除、updatedLot 回 null）。
- clamp：容差內的有效賣出股數＝持有股數；trade 上記的 sharesSold、等比縮減的
  分子一律用 clamp 後的值（成本基礎比例永不超過 100%）。
- SHARE_EPS 與 fmtShares 一律 import 股數單位模組（單一出處，禁止寫死數字）。

不做：
- 費稅公式、匯率換算、當沖判定與夾制、SellResult 形狀——零變更。
- 賣出視窗 UI 邏輯（「全部」鈕本來就精確往返；「持有 X 股」顯示已在票 02）。
- 匯入重播引擎（票 01 已處理，兩邊語意獨立）。

## 驗收

- 新增行為鎖案例（美股碎股批次，期望值先手算；既有案例**零修改**——
  整數與精確值路徑行為不變是設計保證，台股既有案例就是證明）：
  - 精確滿賣：持有 1.2048、輸入 1.2048 → 全賣、updatedLot 為 null。
  - 容差滿賣＋clamp：輸入 1.2048005（差 5e-7）→ 全賣、trade.sharesSold ＝ 1.2048。
  - 超賣仍擋：輸入 1.2049（差 1e-4 > 容差）→ 拋錯。
  - 部分賣出照舊：輸入 0.5 → 批次剩 0.7048、成本／股利等比縮減。
- `npm run gate` 全綠。
- 收尾 `code-review`，merge 帶 `Code-Review:` trailer。
