# 03 日常入口與 App 操作紀錄

## 啟停與例外

- 定稿啟動器在相同 `4431/4432` 埠先後啟動兩次。第一輪 owned PID `32220/34456`，五條正式函式並行預熱全部 204、3183 ms；停止回報 `stopped: true`。第二輪 owned PID `22692/33824`，五條全部 204、3166 ms；停止亦回報 `stopped: true`。每輪的 Vercel／Vite 日誌各有唯一名稱，ready 不讀前輪標記。第二輪預熱後第一支固定台股 chart 經前端代理為 200、0.210 秒（只供路徑煙測，不當 App 可見成績）。
- 佔用 `4420` 埠的本案測試 HTTP 服務存在時，啟動器對 `4420/4421` 立即拒絕，輸出「指定埠已有 listener；不接管其他服務。」原佔用服務仍可回應「占用測試」，隨後只停止該測試服務。
- 最終檢查本案使用過的 `4385～4435` 測試埠沒有 listener，`daily/state.json` 不存在。沒有碰使用者的 `3000/3001` 服務。啟動器只終止自己記錄且再次核對程序命令與建立時間的 PID。
- 修訂後的 `4451/4452` 日常入口五路由 OPTIONS 全為 204，預熱 3023 ms；暖 OPTIONS 與固定 GET 各 20/20 成功，隨後 stop 回報 `stopped: true`。`stale03-20260924-r1` 另以 `4445` 模擬舊 listener 存活、控制管道失聯；啟動器拒絕在 `4447/4448` 另起服務，舊狀態檔與 listener 保留，測試結束才清掉測試造出的檔與 listener。
- 最終成本 run 使用 `4521/4522`：五路由 OPTIONS 預熱皆 204、3112 ms；`daily03-cost-20260924-r4` 在測量前後讀取同一輪狀態，記錄監督 PID `30536` 與子程序 PID `29404/35936`，身分保持一致，20/20 暖 OPTIONS 中位 15.016 ms、20/20 固定 GET 中位 60.646 ms，停止回報 `stopped: true`。原始檔僅保存 PID／建立時間，不保存控制 token 或後端密鑰。

## 正式 App 固定資料路徑

- 每次測試用新埠與新瀏覽器來源。`4393` 來源：台股 `2330.TW` 顯示 `FIXTURE 2330`、固定價格 `901.00` 與 K 線；切換美股 `AAPL` 顯示 `FIXTURE AAPL`、固定價格 `588.00` 與 K 線。`/api` 同源代理帶頁面 Origin 回 200；`Origin: http://evil.invalid` 仍回 403。
- 同一隔離來源的「我的庫存」起初為空；只在此新來源建立一筆固定 AAPL、1 股、測試成本 500 的持股，庫存列隨即顯示固定價格 `588.00`。此操作沒有觸碰既有正式來源的真帳本，固定匯率只供路徑煙測，不拿損益數字驗金融語意。
- `4395` 新來源：台股固定 K 線載入後，選「空手」並啟動 AI 分析；畫面出現「AI 技術分析報告」及「假片段1～5」。對應的固定探針記錄 `child.fakeCli.spawn=1`、`delta=5`、`done=1`。`PERF03_TEST_CLI=1` 把 provider 強制導向假 CLI，沒有呼叫真 AI。
- App 畫面只證明正式元件能透過新日常入口接到候選，沒有完成十檔冷庫存／十檔 K 線 B1↔C 的可見時間配對。那些全案效能目標仍 OPEN。

## 來源與隔離

日常後端由同一工作樹的全域 Vercel CLI 55.0.0 與 `@vercel/node` 5.8.23 載入正式 handler；預載 `persistent-functions.cjs` 只給後端。前端 Vite 的程序環境採明確白名單：必要作業系統變數、公開的 `VITE_` 變數及代理位址；後端與測試金鑰不傳入前端程序。固定資料模式另由後端預載測試探針。隔離重載 run 的 `C:/pfv7` 十一個候選產品／測試檔與主工作樹逐檔 SHA-256 相同，run 結束沒有留下 `.env`、`.vercel` 或被測檔案差異。
