# 04 — 降低報價與匯率的單次請求成本

Status: ready-for-agent
Blocked by: 03
Type: task

## 要交付的行為

維持三槽與資料完整，在日常入口降低每支 quote／FX 的 TTFB，使十檔全價不再因四波高成本請求累積到十多秒。

## 工作

- 先重量日常候選的十／三十檔固定上游；若既有 handshake 重用已使可控成本達預算，不為增加修改數而重寫 quote path。這只決定是否再改碼，真行情與正式 App 的新目標仍由 07 裁定。
- 只針對分段證據裡剩餘的大段選修：重複握手、重複查詢、同 key pending 未共享、額外 proxy 往返、可證實的序列等待。一次一變因。
- 正常 cold、同頁 warm、force 分列；quote／FX 的有效完成與名稱補齊分列。名稱流量仍計入實際網路上限。
- 核對 upstream 次數、HTTP peak、錯誤率、每檔成功與日期；減少請求必須來自合法共享，不能漏資料或藏內部併發。
- 固定回應鎖 force 重疊、連續 force、移除／重加、卸載、名稱晚到、FX 失敗及 UI／服務快取發布。

## 驗收

- [ ] 被選等待段有 before→after 降低或證明無需再改，完整十檔／FX 與三十檔皆無漏列。
- [ ] quote／FX／名稱合計 HTTP peak≤3；queue 預設及既有 peak=3 期望零修改。
- [ ] fetchedAt、沿用窗、force、世代、快照／健檢、本體鍵及金融結果不變。
- [ ] 必要 provider 的狀態、次數、重試與延遲逐列可核對；不能只報 browser request 數。
- [ ] 固定正反案例、隔離 gate、獨立雙軸覆核及精確提交完成。完整真行情留到選定候選的最終票。

## 停手

三槽內剩餘主要為不可控上游時，交付下限及未達標數字；不把提高併發、擴快取或減少成功條件塞進本票。
