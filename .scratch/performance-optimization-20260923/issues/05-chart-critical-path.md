# 05 — 縮短 K 線安全可控的必要路徑

Status: ready-for-agent
Blocked by: 04
Type: task

## 要交付的行為

在保留有效價量及 context 的前提下，消除有證據的純名稱阻塞、重複上游工作或資料處理／繪圖成本，讓冷搜尋實際變快。

## 工作

- 用日常候選量搜尋解析、2y／10y、PV／法人／名稱、enrich、React commit／rAF；台／美與五種週期分列。
- 純名稱若對首屏貢獻至少 200 ms 或 10% 等待，先明定同股票／世代 late-name patch 的窄契約，再用 pending 紅燈驗證名稱不 gate 有效 K 線。名錄可命中就用；不可為了 metadata 預載更多真請求。
- late-name 只改名稱，不改 K 線 data、日期、完整旗標、fetchedAt 或快取沿用窗，也不能觸發 AI／錯誤健檢失效。
- PV／必要法人資訊仍保持原完整性；沿用已核准失敗短快取與取消語意。若必要資料是慢段，處理可證實的重複工作，不能刪 await 提前假裝完整。
- 只有資料處理／繪圖段至少 100 ms 且占首屏 20% 時，才針對 profiler 找到的單一熱點優化；否則不做泛用 memo 或重寫圖表。

## 驗收

- [ ] 可見面板上的同方法 before／after，明確指出改善的段與剩餘等待，不把 API 結束冒充畫面完成。
- [ ] 固定成功輸出逐欄／hash 一致；台／美及日／週／月／1 時／15 分均通過。
- [ ] 2y／10y 任一先到／失敗、PV／法人／名稱故障、背景刷新、A→B→A、多訂閱／個別取消皆保持。
- [ ] late-name 紅燈可判舊版本失敗（若採用此分支），舊名稱無法污染新股／新世代／快取。
- [ ] 暖回訪無多餘 chart；已被 10y 取代的 2y 取消仍有對應證據，未吞其他錯誤。
- [ ] 隔離 gate、獨立雙軸覆核與精確提交完成。若安全可控段不存在，仍要記實測下限；最終 K 線目標未達就保持 OPEN。
