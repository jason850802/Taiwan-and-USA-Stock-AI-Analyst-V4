# 實際等待時間優化的決策路線

## 目的地

交付可在日常入口使用、達成新 PLAN 效能目標的本機方案，並保留行情、金融、本體資料與 API 契約。使用者明確要求完整可交辦計畫；實作順序與驗收入口在 [PLAN](PLAN.md)，每張工作票同時回答一個選路或交付問題。

## 說明

使用 diagnosing-bugs 先建立可判紅迴圈；使用 implement／code-review 逐票實作與獨立覆核。初始已知瓶頸與未證實事項在 [現況稽核](STATUS-AUDIT.md)。採用前不執行產品修改或真行情。

## 已完成的決策

尚無本輪實作決策結案。舊產品成果全部保留；本輪門檻不得由候選成績反向調低。

## 尚待證據決定

- 本機 dispatch 與重複 Yahoo 握手各占多少，由基線分解票回答。
- 同 handler 長駐能否在不改契約下達目標，由原型票回答。
- 日常入口更換後是否還需 quote／K 線修改，由後續成本票依分段數字決定。
- 若剩餘為不可控上游、三槽下無法達標，先交下限與限制；任何新的架構或併發決策另開票，不猜測預先實作。

## 範圍之外

正式部署／發版、換 provider、新增套件、改金融語意、提高 queue 預設、真 AI、真帳本與不具量測依據的重寫。
