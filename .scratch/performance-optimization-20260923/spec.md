# 第二輪效能優化規格

Status: ready-for-agent — 已採用；01 基線票完成（B1 判紅）；02 長駐原型完成（58/59 契約案例完全等價＋1 個已知差異、本機兩項目標對候選 PASS；取消契約兩入口都 FAIL，03 採用前必修），下一票 03 接入日常入口；全案仍 OPEN。目標與依賴見 [PLAN](PLAN.md)。

## 使用者問題

目前有效量測的庫存首價約 4.42 秒、十檔與匯率全價約 16.64 秒；K 線首批／完整約 4.6～5.1 秒。已做的名稱解耦與正確性修正要保留，本輪須降低實際日常入口的冷請求等待。

## 要改變的行為

1. 本機 API 不應在每一支請求重付可避免的程序／模組初始化與 Yahoo 握手成本。先量再改，正式 handler 是唯一業務邏輯來源。
2. 日常開發入口應與驗收入口一致，程式或設定變更後能載入新版本；失敗時明示且不能繼續提供舊碼。
3. 報價與 FX 維持三槽，但每個槽的有效工作時間降低。名稱仍獨立補入，不得占用無界背景連線。
4. K 線只消除純 metadata 或重複工作的等待。必要 OHLC 修正、籌碼缺值辨識、完整歷史契約保持；不把未校正資料宣稱為正式行情。
5. 正式 App 的冷搜尋、切週期、回訪、強制更新、庫存與資料保護皆有可見畫面證據；不能只證明探針快。

## 本機長駐候選的相容性契約

- 路由集合、方法、URL decode、重複 query 參數、headers、JSON body、錯誤 body／status、CORS、cache header 與正式路由一致。未知路由、錯誤 body、過大 body 的行為有固定案例。
- 重用現有 `applyGuards`；守門序為 CORS → OPTIONS 短路 → 來源 → secret → rate limit。拒絕案例不得打上游。
- 每個 request／response、AbortSignal、trace 與錯誤彼此隔離；SSE chunk 必須即時 flush，取消後不殘留本次工作。測 AI endpoint 只注入假 provider。
- Yahoo cookie／crumb generation、同時 pending 共用、10 分鐘 TTL、401／429 invalidation 與重試次數照現有契約；不增加新的行情快取或延長金融沿用窗。
- 共用模組狀態要列清單：認證世代、rate limiter、provider client、設定及任何 pending。持久化符合各模組設計，但不能讓某請求的 token／response／abort 污染另一請求。實際計數是效能證據的一部分。
- 啟動只 bind localhost；後端環境與私密值不送進前端。不得把完整環境 dump、cookie、crumb、token 或秘密雜湊寫進證據。
- handler／依賴／設定變更或刪除後，必須重新載入與驗身分；失敗則停用候選服務並顯示錯誤。產品化前驗 stop／restart／埠衝突／錯誤恢復。不能依賴手工複製一份舊 runtime。

## 報價優化允許範圍

先利用已存在的握手快取／pending，去除已證實的重複握手或請求準備成本。若原型已使主要目標達成，保留成果，不再為票數改寫報價快取。

同 key、force、重疊刷新、已開始工作占槽到完成、移除／重加、卸載、舊價格／名稱不可污染新世代，全部維持。名稱更新不得重設 fetchedAt、沿用窗、健康簽章或寫回持股。FX 仍先入列、同三槽，失敗沿用規則不變。

不新增 quote 批次 API 或把 N 個 provider 呼叫藏在一個 browser request 中避開上限；真正減少請求只可來自既有合法去重／已有效資料，必須保留每項資料來源與等價輸出證明。

## K 線優化允許範圍

保留已核准的 FinMind PV transport failure 降級顯示與 10 分鐘短快取，AbortError 原樣取消，不啟動多餘 fallback。籌碼不可用保持明示，分析輸入不可把缺失當零。

可評估純名稱離開首屏必等路徑，但需先量得貢獻，並先在同票寫出窄介面決定：既有 Yahoo／名錄名稱先顯示，晚到只 patch 同股票、同世代的名稱；不改 K 線陣列、OHLC、fetchedAt、完整狀態、快取沿用窗或自動啟動 AI。若目前訂閱／快取介面無法做到，提出接縫及紅燈案例後才實作；不能直接刪 `await Promise.all`。

FinMind PV／法人資料、2y／10y 的先到規則、多訂閱與個別取消仍為硬契約。若資料轉換或繪圖占主要時間，只針對已定位的熱點處理，固定輸出與圖表資料保持一致。未證實的 CPU 問題不進本輪。

## 本體資料驗收

只操作新 origin 的合成資料。每項操作保存五鍵原始字串的 before／after，按操作分類：

- 搜尋、切股、週期、讀報價、回訪與名稱補入：五鍵逐字一致。
- 刻意新增／移除合成持股、保存合成快照：只允許預先列出的鍵與資料 delta；其他鍵逐字一致。不能對預期寫入操作硬要求全部鍵不變，也不能只記 boolean／鍵名充數。
- 健檢失效、S1 世代與 P1 證據身分保持。只用假 AI，不打真帳本 origin。

新 PLAN 的數值門檻、固定輸出、原測試、正式 App、完整 gate、獨立 Standards／Spec 覆核全部通過，且日常入口能重跑，才稱本輪完成。若上游占據不可避免的等待，交付量測下限與限制並維持對應效能目標 OPEN。
