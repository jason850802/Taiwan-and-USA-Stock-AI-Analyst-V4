# 02 — 逾時失敗要能自證：log 帶秒數與「當時收到了什麼」

Status: resolved（2026-08-15）
Blocked by: 無（票 01 已合入分支 `d2b2c2b`；本票不碰票 01 動過的 parseLine 與常數值）

> **本票在票 01 之後依實戰經驗改寫過**（2026-08-13）。原版只要求「補上逾時字樣與秒數」，
> 實戰證明那還不夠——真正卡住診斷的是「不知道當時到底收到了什麼」。改寫理由見下。

## 目標

讓三個逾時出口在後端 log 裡**自己說清楚發生什麼事**：等了多久、**期間收到了什麼**。
目標不是「多印一行」，是讓下一個人**看一眼 log 就能分辨**「上游死了」與
「上游活著但我們沒等夠久」——這兩者的處置方向完全相反。

## 為什麼值得做（實戰代價，非假想）

2026-08-13 診斷健檢全面失敗時，後端 log 只有：

```
[gemini:UPSTREAM_ERROR] AI 服務暫時無法回應，請稍後再試。
```

——沒有秒數、沒有原因、沒有「收到過什麼」。結果**連續走錯兩個方向**：

1. 先誤判成「`CLAUDE_CLI_PATH` 沒設」——查了才發現探索有三層 fallback，
   而且真的找不到執行檔時丟的是 `MISSING_KEY` 不是 `UPSTREAM_ERROR`。
2. 再誤判成「訂閱登入過期」——查 `.credentials.json` 才排除。

真因（首塊閘門只認文字增量、模型先思考數十秒）是靠**繞過 App 直接叫 CLI 計時**
才挖出來的，前後花掉數輪往返。**若當時 log 寫的是
「首塊逾時 45 秒（期間收到 23 個增量，其中 0 個是文字）」，第一眼就破案了。**

## 現況（已讀碼確認，三個出口都是沉默的）

| 出口 | 位置（角色） | 現況 |
|---|---|---|
| 非串流總逾時 | LLM 橋接層的非串流函式 | 丟**不帶訊息**的分類錯誤 |
| 串流總逾時 | LLM 橋接層的串流函式 | 丟**不帶訊息**的分類錯誤 |
| 串流首塊逾時 | 同上 | 丟**不帶訊息**的分類錯誤 |

同檔其他失敗出口（spawn 失敗／CLI 無輸出／輸出無法解析）**都有**帶原因的訊息，
只有這三條例外。所以 log 只印出使用者文案時，那就是逾時的指紋——但要人事先知道
這個冷知識才看得懂，這正是本票要消滅的。

## 範圍

做——三個出口都補上訊息，且**訊息要含「等了幾秒」與「當時收到了什麼」**：

1. **非串流總逾時**：秒數 ＋ 已累積的 stdout／stderr 長度
   （例：`claude CLI 逾時 100 秒（stdout 0 字、stderr 0 字）`）。
2. **串流總逾時**：秒數 ＋ **已產出的文字字數**（串流函式已有累積文字變數可用）。
   這條要能回答「是慢到跑不完，還是根本沒在產出」。
3. **串流首塊逾時**：秒數 ＋ **期間收到的串流增量數**。
   增量計數器目前不存在，**需新增一個**（在 parseLine 認到 `content_block_delta`
   時遞增即可；票 01 已把該分支改成「任何增量都進來」，計數器放那裡最自然）。
   這條要能回答「是完全沒聲音（真卡死），還是一直有動靜（我們等太短）」。

其他：
- 秒數一律**由既有常數推導**，不得寫死數字（常數改了訊息要跟著改）。
- 訊息一律走同檔既有的**消毒＋截斷**函式再輸出，比照其他帶細節的出口。

不做：
- **調整任何逾時常數的數值**（見紅線 1）。
- 票 01 已定案的 parseLine 判定邏輯（只加計數器，不動判定條件）。
- 錯誤分類碼（仍是同一個碼，只是訊息更具體）。
- 使用者看得到的前端文案。
- 任何前端、hook、元件檔案。

## 紅線

1. **不得改動三個逾時常數的數值**（現為 100／300／45 秒）。300 秒是票 01 由使用者
   拍板的結果，且**已有行為鎖測試綁定**——動它會紅燈。要調數值是另一次語意決策。
2. **不得讓秘密進 log**。訊息一律經既有消毒函式，不要自己拼字串繞過。
3. **分類碼不變**。前端依碼決定文案與重試提示，改碼會連動 UI 行為。
4. **既有測試零修改**——除了下面驗收明列要「加強斷言」的那三條逾時測試。
   那三條目前只斷言分類碼，補上訊息斷言是加嚴不是改期望值；
   **若有其他測試轉紅，停下來問使用者。**

## 與原版的差異（改寫理由）

| 項目 | 原版 | 現版 | 為什麼改 |
|---|---|---|---|
| 訊息內容 | 「逾時字樣＋秒數」 | **再加「當時收到了什麼」的計數** | 光有秒數仍分不清「上游死了」與「等太短」——實戰就是卡在這 |
| 現況描述 | 「串流兩個出口**若**也是空訊息」 | 已讀碼確認**三個都是**空的 | 票要寫事實，不要寫猜測 |
| 取證方式 | 「把常數暫時改到 1 秒跑一次」 | **改用既有假時鐘測試斷言訊息** | 常數現在有行為鎖綁定，暫改會紅燈；且改常數違反本票自己的紅線 |
| 首塊測試 | 無 | 新增「零增量 → 訊息顯示 0 個」 | 兼作票 01 修復的反向護欄 |

## 給接手方的提示

- 同檔已有數個帶細節的失敗出口，訊息組法照抄那些（含消毒與截斷），
  本票只是「別讓逾時成為唯一的沉默出口」。
- 這是純觀測性改動，**使用者在畫面上看不到任何差別**——那是預期的。
- 票 01 的教訓值得記住：**當時的量測方法與後端的判定條件不一致，就會得到看似
  精確、實則錯誤的結論**。寫這張票的測試時，斷言的是「後端實際輸出的訊息字串」，
  不要自己另建一套推導。
