# 02 — LLM 橋接層的逾時出口補上 log 細節

Status: ready-for-agent
Blocked by: 無（與票 01 平行，不碰同一批檔案的同一區塊）

## 目標

讓「逾時」在後端 log 裡能被一眼認出，不必再靠逐條排除法定位。

## 規格依據

spec.md「觀測性（票 02，獨立）」節。

## 背景（讀碼前先知道）

**LLM 橋接層**的所有上游失敗出口都會把原因寫進丟出的錯誤訊息——
spawn 失敗、CLI 無輸出、輸出無法解析，log 都看得到原因。

**只有逾時那條例外**：它丟的是不帶任何訊息的分類錯誤，於是後端 log 只印出
使用者看的通用文案（「AI 服務暫時無法回應，請稍後再試。」），
**真正的原因被吃掉**。

實際代價：2026-08-13 診斷健檢失敗時，因為 log 沒有細節，先後誤判成
「執行檔路徑沒設」與「登入過期」兩個錯方向，繞了兩圈才靠實測定位到逾時。

## 範圍

做：
- **非串流路徑**的逾時出口：丟出的分類錯誤補上細節訊息，需包含
  **「逾時」字樣與實際秒數**（例如「claude CLI 逾時 100 秒」）。
- **串流路徑**一併檢查：總逾時與首塊逾時兩個出口若也是空訊息，同樣補上，
  且訊息要能區分是「總逾時」還是「首塊逾時」（兩者的處置方向不同）。
- 秒數由既有的逾時常數推導，**不得寫死數字**（常數改了訊息要跟著改）。

不做：
- **調整任何逾時常數的數值**（票 01 的驗收才會產生該不該調的數據，
  且那是使用者的語意決策）。
- 使用者看到的前端文案（維持現狀）。
- 錯誤分類本身（仍是同一個分類碼，只是訊息更具體）。
- 健檢、串流接線、任何前端檔案（票 01 的範圍）。

## 紅線

1. **不得讓任何秘密進 log。** 訊息一律走既有的消毒函式再輸出，比照同檔其他
   帶細節的失敗出口的寫法——不要另闢蹊徑自己拼字串。
2. **分類碼不變。** 前端依分類碼決定文案與重試提示，改碼會連動 UI 行為。
3. **既有測試零修改。**

## 驗收

- [ ] 非串流逾時出口的訊息含「逾時」與秒數，且秒數由常數推導（改常數即改訊息）。
- [ ] 串流的總逾時／首塊逾時兩個出口訊息可互相區分。
- [ ] 訊息一律經消毒函式輸出。
- [ ] **人工取證**：把逾時常數暫時改到極小值（如 1 秒）跑一次健檢，
      確認後端 log 印出帶秒數的逾時訊息；**取證後把常數改回原值**並在票面
      註明已還原。
- [ ] `npm run gate` 全綠。
- [ ] 收尾 `code-review`（雙軸 Standards＋Spec），merge 帶 `Code-Review:` trailer。

## 給接手方的提示

- 同檔已有數個帶細節的失敗出口，訊息組法照抄那些即可（含截斷與消毒），
  這張票的重點只是「別讓逾時成為唯一的沉默出口」。
- 這是純觀測性改動，使用者在畫面上看不到任何差別——那是預期的。
